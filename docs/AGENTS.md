# docs/ 目录规范（给 AI Agent）

> **除非用户明确同意，不要新建任何文档**（本目录、仓库根、或任何子目录都不要）。
> 这是用户反复强调过的口径：文档一多就没人看，最后变成误导。

## 硬性规则

1. **不要新建文档。** 需要记录的内容一律追加到 `更新记录.md`（**最新批次写在最上面**）。
   确实想新建文件时（设计文档、方案对比、README 之类）：先在回复里说明「为什么非新建不可」
   并等用户同意，再动手。
2. **不写过程性文档。** 构建日志、踩坑流水账、实测截图说明、逐轮调参记录 —— 这些属于
   提交信息，最多压缩成 `更新记录.md` 里的 1~3 条要点。
3. **历史提案落地后要收敛。** 旧的设计/建议文档在结论并入代码或 `更新记录.md` 之后，
   原文件删除；细节靠 git 历史与代码注释回溯，不要留"过期但很长"的文件。
4. **`更新记录.md` 是唯一变更日志**，每条写清「改了什么 / 为什么 / 可感知的影响」，
   并按批次标注对应的回归用例名。它是日志、会一直变长，**这是唯一允许长的文件**——
   但每条控制在 1~5 行，别把设计文档整段搬进来。

## 本目录现在应该只有这些

| 文件 | 作用 |

| `更新记录.md` | 唯一的变更日志（要点式，最新在上） |

> 想加文件？先问用户。默认答案是「不」。
