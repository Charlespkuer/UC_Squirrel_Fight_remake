## 1. 一场战斗的完整流程

### 1.1 战斗体（fighter）字段

`js/sim.js:104-179 makeCombatant(f, side)`。玩家侧由 `js/main.js:669-679` 构造：

```js
me = {
  name, level,
  power, agility, speed,          // = State.totalStats()（装备＋被动＋药剂）
  hp, maxHp,                      // 关卡连战：hp 是继承后的当前血量
  baseStats: { power: S.power, agility: S.agility, speed: S.speed },  // 裸属性
  weapons: [{id, level, harmLo, harmHi}],
  skills:  [{id, level}],
  npcType, wears,
  effects: State.equipmentEffects(),   // 装备词条 id → 数值
  masterLevel
}
```

- `baseStats` 是**裸属性**（不含装备/被动/药剂），只被「真·色诱之术」脱装备时使用（`sim.js:226 stripped()`）。
- `effects` 同时承载「装备词条」和「塔内技能加成」，见 §6 / §10。
- 塔内玩法在 `adjustMe` 里继续改写这些字段（`js/tower.js:1000-1120`）。

### 1.2 行动条（速度决定出手顺序）

`js/sim.js:1233-1245`：

```
若双方行动条都 < 100：
    elapsed = min((100-A.ap)/speedA, (100-B.ap)/speedB)
    A.ap += elapsed*speedA ; B.ap += elapsed*speedB
出手方 = ap 更高的一方（平局时玩家 0 先手）
出手方 ap -= 100
```

- 速度只影响**出手频率**，不影响伤害。
- 全场最多 **120 次行动**（`MAX_ACTIONS = 120`，`sim.js:607`）；超时按「剩余血量比例」判定胜负（`sim.js:1322`）。
- `immediate` 追加行动（装死、小宇宙、来点松果、野球拳真·连击、先机预判、疾风先手…）**不消耗行动条**，且跳过沉默/缴械/脱装的回合递减（`sim.js:1293-1294, 1312`）。

### 1.3 一次出手内部的固定判定顺序

以武器为例（`js/sim.js:1014-1120`）：

1. **选类**：武器 / 技能 / 普攻（§3）。
2. **选具体武器**（权重见 §3.2）。
3. 方天画戟（1）首次被选中 → 本回合变成「蓄力休息」，下次强制出武器（`sim.js:1024-1028, 1012`）。
4. 伤害基数 `R(lo,hi)` → 力量乘区 → 固定加值 → 词条乘区。
5. **命中判定**（必中武器/必中 buff 跳过）。
6. **暴击判定**（倍率 2×，可被真·暴击抬到 4×）。
7. **连击判定**（西瓜刀 2 段、流星锤 3 段）。
8. 每段走 `applyDamage`：塔 `dmgMul` → 技能暴击/词条 → 减伤链 → 护盾 → 装死/复活。
9. 武器附带效果（降属性、毒、晕、沉默、吸血、自伤）。
10. **反击判定**（近战且非大榔头/死神镰刀才可被反击）。
11. 结算词条类额外行动（疾风先手）→ 写入回合事件。

## 2. 通用判定公式

随机约定：`R(lo,hi)` 为闭区间整数均匀随机；`chance(p)` = `Math.random()*100 < p`（`sim.js:41-42`）。

### 2.1 有效属性

```js
effPower(c) = max(1, round( (裸属性或含装备属性) × (1 - debuffs.power/100) + buffFlat.power ) × 其它乘区 )
```

- `stripped(c)`（真·色诱）：改用 `baseStats`，且装备词条全部失效（`sim.js:225-226, 341`）。
- `debuffs.*` 是百分比扣减（菜刀/死老鼠/屎坨坨），同类只取**最大值**（`sim.js:1105-1107`）。
- `buffFlat.*` 是小宇宙、狂暴、塔增益的加值。
- `effAgility` / `effSpeed` 同构（`sim.js:329-340`），额外吃塔「狂怒」的低血乘区。

### 2.2 命中 / 闪避（`sim.js:474-485`）

```
dodge% = 6 + 26 × Agi_def / (Agi_def + 1.2 × Agi_att + 40)
dodge% ×= (1 + (shift + swordDodge + meteorDodge)/100)      // 相对提升，不是加百分点
dodge% += dodgeBonus                                        // 塔「闪避精通」等，加算
dodge% ×= (1 + dodgeMul)                                    // 塔「烟幕」
dodge% = clamp(dodge%, 0, 55)                               // 硬上限 55%
```

- `shift = (5 + 2×(移形换位等级-1)) × (1 + effect35/100)`，仅有技能 11 时。
- `swordDodge` = 木剑命中后的自身闪避增益；`meteorDodge` = **被打者**吃了流星锤之后整场 +20（`sim.js:1064`）。
- **必中**条件（`dodgeChance` 直接返回 0）：`mods.mustHitAll`、`mods.firstStrikeAll`、`mustHitNext`（师父驾到后的下一击）、武器 9 / 15。
- 同敏捷下的基准闪避：20 敏捷 ≈ 12.2%、50 敏捷 ≈ 14.7%、100 敏捷 ≈ 16.0%；敏捷碾压对手时约 21.9%。
- 命中只在出手时判定**一次**；连击武器的每一段各自走减伤链，但共用这一次命中判定。

### 2.3 暴击（`sim.js:487-492`）

```
critChance = 5 + 2×暴击技能等级 + 塔 critBonus
```
- 激光剑（11）：`critChance += 20 + 2×(min(等级,10)-1) + 3×真等级`。
- 暴击倍率：
  - 普攻：`2 + effect1/100 + critDmgBonus`
  - 近战武器：`2 + effect2/100 + critDmgBonus`；投掷：`2 + effect3/100 + critDmgBonus`
  - **技能**：伤害在 `applyDamage` 内判定，倍率 `2 + effect4/100 + critDmgBonus`，且吃防守方「真·皮糙肉厚」的暴击压制。
- **真·暴击（技能 9）的 4 倍**：真1~真5 = 10%~50% 概率，但这段代码只在**技能**分支里（`sim.js:630-639`）——
  武器与普攻即使学了真·暴击也不会出 4 倍。
- 注意不对称：**真·皮糙肉厚的反暴击同样只作用于「技能」**，不压制武器/普攻的暴击（`sim.js:632-633`）。

### 2.4 反击（`sim.js:948-968`）

- 反击率：普通 25%，熊猫（`npcType === 'xm'`）45%。
- 触发前提：本次为近战武器且武器不是大榔头（2）/ 死神镰刀（15）；或技能未落空且无伤害豁免。
- 反击伤害：`effPower(防) × (0.6+R(0,0.4)) × (1 + effect5/100)`；有技能 24 时再 `×(1.5 + 0.06×(等级-1))`。
- 被反击方可以再闪避一次，概率 = `dodgeChance(防,攻) × 0.5`。
- 反击本身会走完整减伤链，也可能触发绝对防御/龟甲/装死。

### 2.5 伤害乘区与减伤链（`sim.js:624-767, 546-590`）

按顺序：

1. 塔 `att.mods.dmgMul`（对机制/精英/侠客的增伤）乘算。
2. **技能**专用：`×(1 + effect8/100)`（技能伤害词条）＋暴击判定。
3. `dmgReduce(def, dmg, {action, weaponType})`：
   1. 装备减伤词条：武器 → `effect9`（近战）/`effect10`（投掷）；技能 → `effect11`；普攻 → 无。上限 80%。
   2. **绝对防御（16）**：概率 → 伤害归 0，并把 `round(dmg × (40+4×(等级-1))%)` 反弹给攻击者。
   3. **龟甲术（7）**：概率 → 减免 `clamp(20+5×(等级-1), 0, 80)%`。
   4. **皮糙肉厚（10）**：减免 `clamp((5+(等级-1)) × (1+effect34/100), 0, 80)%`。
   5. 塔 `takenMul`（铁布衫等）乘算。
   6. 塔 `lowHpTakenMul`：**按越过血线分段结算**（`lowHpTakenDamage`，`sim.js:314-328`）。
   7. 题面·熔核的逐回合减伤。
   8. `dmg = max(1, dmg)` —— **减伤再高也至少掉 1 点**（绝对防御归零那一条除外）。
4. 塔「狂怒」低血终乘：`dmg × (1 + lowHpFinalMul)`。
5. 塔「风影身法」首次受击必定闪避 → 伤害归 0。
6. 塔「先机预判」首次伤害为 0 → 伤害归 0，并给防守方一次追加行动。
7. 护盾吸收（石像鬼/T 坚韧壁垒）。
8. 扣血，并处理装死 / 复活甲 / 无敌模式。
9. 反伤（荆棘铁壁 15%、塔荆棘之甲、题面镜鳞、绝对防御反弹）打在**攻击者**身上，可被「反噬豁免」全部免疫。
10. 吸血：`吸血% = 30%(机制) + mods.lifestealPct + 低血吸血`，回复 `dmg × 吸血%`（受 `healMul` 影响）。

### 2.6 治疗与吸血

所有治疗都走 `healOf(c, amount)`（`sim.js:228`）：`round(amount × healMul)`，`healMul` 由塔「涌泉烙印」/题面枯泉写入（枯泉 = 0 = 完全封疗）。

## 3. 出手选择：武器 / 技能 / 普攻的概率

### 3.1 出手类型：三方权重竞争（不是固定百分比）

`pickKind`（`sim.js:411-440`）把「武器池 / 技能池 / 徒手」放进**同一个加权池**抽一次：

```
武器总权重 = Σ weaponWeight（没用过 100；用过 25；刚用过 ×0.3）
技能总权重 = Σ skillWeight（没用过 100；用过 = 二次使用权重：17/12 是 15→5，其余 20；刚用过 ×0.3；C33 加成 ×(1+boost)）
徒手权重   = RULES.commonAttackWeight = 30
命中哪一档 → 再在那一档里按各自权重抽具体招式
```

> 完整数值表（逐状态权重、逐技能档位、徒手敏感度、单件份额示例）见 **[出手权重平衡表.md](出手权重平衡表.md)**。

这套写法天然满足三条设计目标（不需要额外的「全用过」开关）：

| 目标 | 为什么自动成立 |
| --- | --- |
| 持有的武技越多 → 普攻欲望越低 | 工具总权重随件数线性增长，徒手权重是常数 |
| 全部用过一遍 → 普攻欲望比没用过时更高 | 每个候选的权重从 100 掉到 5~25，工具总权重整体缩水 |
| 只有一个主动技、用过之后不该被强制复用 | 它的份额就是它的二次使用权重，不再有「类型抽中技能 → 只能放它」 |

实测占比（`Sim.kindWeights(att, 武器, 主动技)`，可做确定性校验）：

| 配置（全新） | 武器 | 技能 | 徒手 |
| --- | --- | --- | --- |
| 1 武器 + 1 技能 | 43.5% | 43.5% | 13.0% |
| 3 武器 + 3 技能 | 47.6% | 47.6% | 4.8% |
| 6 武器 + 6 技能 | 48.8% | 48.8% | 2.4% |
| 只有 1 技能 | — | 76.9% | 23.1% |
| 只有 1 武器 | 76.9% | — | 23.1% |
| 无武技 | — | — | 100% |

同一配置**全部用过一遍之后**（技能按「用过 1 次」的档位：17/12 → 15，其余 → 20）：

| 配置（全用过） | 武器 | 技能 | 徒手 |
| --- | --- | --- | --- |
| 1 武器 + 1 技能 | 37.5% | 25.0% | **37.5%** |
| 3 武器 + 3 技能 | 51.4% | 31.4% | **17.1%** |
| 只有 1 技能（任意，用过 1 次） | — | 33.3~40% | **60~66.7%** |
| 只有 1 技能（12/17，用过 2 次及以后） | — | 14.3% | **85.7%** |
| 只有 1 武器（用过） | 50.0% | — | **50.0%** |

- 唯一的手感开关是 `RULES.commonAttackWeight`（默认 30 ≈ 旧固定档 12% 在「1+1」时的等价强度）：调大 → 普攻更多，调小 → 更依赖武技。
- **三侠等纯 NPC 分支**没有武器池，仍走独立固定档位：`RULES.npcSkillChance = 30`（30% 技能 / 70% 普攻）。
- 固定循环敌人（挑战塔松鼠）不受影响，按 `pattern` 出招；抽签仍只消耗一次 `Math.random()`，随机序列长度与旧实现一致。

### 3.2 具体招式权重（`sim.js:356-408`）

- 本场**没用过** → 权重 **100**。
- 已经用过 → 权重 = 它的「二次使用权重」（2026-10 三档口径，`repeatRateOf`，`sim.js:391-403`）：

| 对象 | 用过 1 次 | 用过 2 次及以后 |
| --- | --- | --- |
| 武器（全部） | **30**（`RULES.repeatWeapon`） | 30（同左） |
| 来点松果 17 / 野球拳 12 | **15**（`repeatSpecialFirst`） | **5**（`repeatSpecialAgain`，到底） |
| 其余技能（8/14/15/18/23） | **20**（`RULES.repeatSkill`） | 20（同左） |

> 全部 17 件武器**共用同一行**：目前没有「某把武器更少见」的字段，
> 所以低等级旧武器与神装的出现频率完全一样（见 [出手权重平衡表.md](出手权重平衡表.md) §8）。

- **野球拳（12）**：用过 1 次后 15，用过 2 次及以后 5；且从第 2 次起每次出手前都要先过一次「能不能放」的判定，没抽中就整回合被排除（`yakyuGated`，`sim.js:479-486`，敌我都适用）。
- **刚用过的那一个**权重再 ×0.3（`LAST_PENALTY`）。
- **C33 秘技通神**：被选中的技能权重 ×(1+加成)，走 `skillBoost` 通道（`sim.js:404-412`）。
- 塔内固定循环敌人（松鼠 boss）另有冷却：同一技能用过之后要隔 **3 次出手**才能再放（`RULES.skillCooldown = 2`）。
- 一回合内同一技能不能重复（`turnSkills`），但追加行动会被当作新回合。

### 3.3 技能可用性过滤（`sim.js:990-995`）

被排除的情况：小宇宙已用过；来点松果已用过或**满血**；野球拳未通过衰减判定；固定循环敌人冷却中；本回合已用过；沉默中；被塔「压制」锁住。

## 4. 武器总表（17 件）

来源 `js/gamedict.js:52-70`；等级成长算法 `js/state.js:917-933`（等价于 `sim.js:117-123`）。

伤害公式（`sim.js:1047-1058`）：

```
raw = R(lo, hi)
raw = round( raw × (1 + 力量/120) )
若持有「武器好手」: raw += (10 + 2×(等级-1)) × (1 + effect31/100)     ← 固定值，不吃力量
raw = round( raw × (1 + (类型词条(effect6/7) + 武器专属词条(effect[武器id+11]))/100) )
```

- 武器专属词条：`effect[w.id + 11]`，即 id 1→词条12、…、15→词条26（仅武器 1~15 有）。
- 力量 120 时武器伤害翻倍；力量 0 时为 1 倍。

| id | 名称 | 类型 | 基础伤害 | 每级+ | 真级增量（真1..真5） | L1 | L5 | L10 | 真1 | 真5 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

## 7. 面板数值是怎么组装的

### 7.1 玩家（`js/state.js:1407-1441 totalStats`）

```
力量/敏捷/速度/生命 = 裸属性
  + 装备主属性（每件按部位加力/敏/速/生命；橙装宝石再 ×(1+宝石等级×4%)）
  + 被动技能（力王附体/身手敏捷/风驰电掣/身强体壮，×对应 effect27~30）
  + 药剂（opts.useProps 时）：大力丸/敏捷丸/速度丸 +20%（最低 +5），
                            超级版 +40%（最低 +10）
```

- 关卡战与竞技场传 `useProps:false`（`classic-ui.js:765`、`classic-extras.js:183`），所以**药丸不生效**；主动挑战/天梯/塔内生效。
- `baseStats`（真·色诱的落点）取的是**裸属性**：装备、被动、药剂会一起被脱掉。

### 7.2 AI 对手（`js/state.js:2225-2298 genAI`）

- 等级 = 玩家等级 ±2（可夹），最高 70。
- 成长预算与玩家同构：每级 +5 生命、2 点随机（1/4 概率为 +5 生命）、1 点自由点；53/59/65 级改为 8 点自由分配。
- 武技：按等级开放数量随机抽，**55% 概率抽武器、45% 抽技能**；武器/技能初始等级随机 1~上限。
- 装备：`randomAIGears`（`state.js:2302-2343`），穿戴率 `min(0.95, 0.5+等级/40)`；75% 穿最好一档、20% 次档、5% 随机旧档；蓝装 1 条词条、紫装 2 条。
- 挑战/天梯/竞技场共 3 名对手，基准等级 = 玩家 **−1 / 0 / +1**，各自再 ±2 抖动（下限玩家 −1，上限 70）（`classic-ui.js:597-603`）。

### 7.3 关卡 NPC（`js/gamedata.js:89-200`）

- 模型开关 `STAGE_USE_LEVEL_MODEL = true`：
  - 推荐等级 = `[10,15,20][类型] + 星级 − 1`
  - 三围 = `玩家基准(1.53×等级−2.23) × 角色系数[0.70,0.78,0.72] × 类型系数(螳螂1.15/仙鹤0.92/熊猫1.02)`
  - 生命 = `玩家基准(13.58×等级−10.44) × 角色系数[0.90,1.05,1.20] × STAGE_HP_MUL(1.18)`
- 关掉开关则回落到原表 `STAGE_NPC_HP` × `STAGE_DIFFICULTY`（hp0.85/力0.88/敏0.96/速0.96）。
- 连战：不消耗挑战书，胜后**继承剩余血量并回复 25%**（`classic-ui.js:759`），最多复活 2 次（每次 1 挑战书）。

## 9. 挑战塔 / 无尽塔对武器技能的改写（摘要）

塔内数据在 `js/tower.js` 的 `aggregate()` / `nextBattle()` 里折算成 `sim` 认识的 `mods` 与 `effects`。

### 9.1 塔内敌人是怎么长大的（`js/tower.js:838-912 buildFoe`）

```
LT  = 挑战塔 towerLevel(层) = min(70, 28+1.4×(层-1))            // 39 层起封顶 70
      无尽塔 endlessLevel(层) = min(70, 24+1.2×(层-1))          // 39 层起封顶 70
M   = 挑战塔 towerMult(层) = (1+0.03×⌊(层-1)/5⌋)(1+0.04×⌊(层-1)/10⌋)  // 31 层起恒 1.2420
      无尽塔 endlessMult(层) = min(10, 1.5^(⌈层/5⌉-1))           // 31 层起封顶 ×10
KM  = 挑战塔：1            无尽塔：1.07^(层-30)（前 20 层）· 1.09^(超出部分)   // 30 层起才生效

statBase = 1.53×LT − 2.23        hpBase = 13.58×LT − 10.44     （与玩家同一条成长曲线）
力量 = round(statBase × 0.47 × powMul × M × KM × bias.力量 × 精英1.2)
敏捷/速度 = round(statBase × 0.66 × M × KM × bias.敏捷|速度 × 精英1.2)
生命 = round(hpBase × 1.06 × 0.85 × M × KM × bias.生命 × hpRatio)

powMul：三侠 0.60 / 塔顶狂战 0.85 / 其它 boss 1.45
hpRatio：三侠 1；塔顶狂战 1.20；其它 boss = clamp(1.06 + (bias.生命-1)×0.35 + min(0.06, 0.03+0.004×层), 1.04, 1.22)
松鼠武技等级 = 基础等级 + floor((LT−28)/12)，夹 1..15
```

- `bias` 就是 §8.2/§8.3 表里的四元乘数；无尽深度倍率在 40/50/60/70 层约为 **×1.97 / ×3.87 / ×9.16 / ×21.69**。
- 官方平衡验收线（`tools/tower-balance.cjs` 头部注释）：1~5 层整层通关率 ≥55%、10~15 层 ≥15%、20~25 层 ≥8%。

### 9.2 塔内增益 → 战斗字段

- **通用放大规则**：每条数值型 `mods` 的最终值 = `字面量 × 叠层数 × globalMul`，其中 `globalMul = 1.4^(增幅水晶 C15 层数)`（`tower.js:384-386, 469`）。这是塔内数值最重要的一个交互。
- 属性乘区：`powerMul/agilityMul/speedMul/maxHpMul`（加算叠加后一次性乘）。
- 伤害乘区：`dmgMul`（对侠客/机制/精英）、`lowHpFinalMul`（狂怒，终乘）。
- 命中/暴击：`mustHitAll`、`critBonus`、`critDmgBonus`、`dodgeBonus`、`dodgeMul`、`takenMul`（铁布衫）。
- 招式次数：`weaponFreeUses`（疾风先手：前 N 次武器不消耗回合）、
  `weaponBoostUses / weaponBoostPowerMul / weaponBoostMustHit / weaponBoostReflectImmune / weaponBoostFatigueMul`（T01 闪亮登场：前 3 次武器 +50%、必中、免反伤，之后攻击 −20%）。
- 防御端：`shellPct`、`regenPct`、`lifestealPct`、`thornsPct`（上限 60%）、`reflectImmune`、
  `lowHp*`（狂怒/浴血重生/濒死觉悟/铁血护盾，统一阈值 `lowHpAt`）。
- 回合光环：`roundStatPct`（C54 每回合 +1.5%）、`catchUpPct`（C55 补落后项 10%）、`roundMaxHpMul`（C57 每回合双方上限 ×0.9）、`firstDodge`（C56 首次受击必闪）、`firstHitZero` + `firstHitZeroFreeTurn`（C38 挡下首击 + 追加一次行动）。
- `mods` 通道里**只有 5 条增益直接影响武器/技能触发**：M02 / T08（`weaponFreeUses`）、T01（`weaponBoost*`）、C32、C33，加上 C38 的追加行动。
- 选取型强化：
  - **C32 神兵淬炼**：`run.weaponBoost[武器id] = 1.0` → `adjustMe` 里折算成 `me.power ×(1+1.0)`（**等价于全场力量翻倍**，不是只强化那把武器）。
  - **C33 秘技通神**：候选只有主动技 + 绝对防御(16)/龟甲术(7)/小宇宙(14)；加成写进**独立通道** `me.skillBoost[技能id]`（不再写 `effects`）。主动技由 `skillWeight ×(1+加成)` 提高出手份额；防御技由 `passiveSkillBoost` 提高触发率（16 每次 +150%、7 每次 +200%，封顶首次 90%/再次 45%）；小宇宙改为「开战第一招必放」。
- 永久增益槽位默认 **5 个**（`PERMANENT_SLOTS`），叠层默认上限 **3**（`STACK_MAX`，C26~C29 例外为无限）。
- 易碎烙印：C39~C44 力/敏/速 +8%/+14%（破碎后翻倍）、C49 终焉烙印（力/敏/速/上限 +25%，破碎 +50%，**终乘、按层加算 `1+0.25n`、无次数上限**）、C52 涌泉（治疗 +10%，破碎 +20%）、C53 淘金（试炼币 +15%/+30%）；每场结束 **6%** 概率破碎。
- 无尽环境词缀：共 **10 条**（数值区间见 `js/tower-data.js:115-147`）；5 层起每场战斗后按
  `envChance = min(80%, 14% + (层数-5+1)×6%)` 触发 —— **第 15 层就到 80% 上限**；15 层起可同时存在 2 条。
- 出战结构：挑战塔/无尽塔每层 **4 场**（三侠 3 场洗牌 + 随机 boss 1 场），10 的倍数层追加第 5 场「狂战松鼠」精英；三侠大招命中会给玩家留下贯穿本层的削弱（`HERO_DEBUFF`：螳螂 −3%~6% 上限累计 −15%、仙鹤 随机属性 −5%~10% 最多 3 次、熊猫 锁 1 件武器/技能最多 2 个）。

## 14. 稀有度权重机制（商店 & 战斗奖励）

### 14.1 旧机制的问题（为什么「降权」几乎没用）

旧做法是**两步**（`tower.js` 的 `rollRarity` + `pickByShopWeight`）：

1. 先按档位权重摇稀有度：`[66, 21, 10, LEGEND_BASE_WEIGHT=2.2]`（传奇再乘 `0.88^已拥传奇`、全拥有 ×0.35、`天命所归` ×2^n、刷新倾斜 `p^i`）→ 归一化后约
   **普通 66.53% / 稀有 21.17% / 史诗 10.08% / 传奇 2.22%**；
2. 再在**该档内**按 `shopWeight × 动态惩罚`（`repeatWeight` / `weightDivBy`）抽一件。

于是调低某个 buff 的权重只会让**同档内**的份额分给别的 buff，**档位总概率一点不变**。
极端情况：该档只剩它一件可用时，`pickByShopWeight` 里 `list.length === 1` 直接返回，
个体权重被**完全忽略**。实测（修复前，`shopPool`）：

| 虚空铭文 C37 的附魔数 | C37 权重 | C37 全局出率 | 传奇档总概率 |
| --- | --- | --- | --- |
| 0 | ×1 | 0.554% | 恒 2.22% |
| 1 | ×1（`÷n` 的 n≤1 不降） | 0.554% | 恒 2.22% |
| 3 | ÷3 | 0.214% | 恒 2.22% |
| 5 | ÷5 | 0.134% | 恒 2.22% |

即：传奇档的「出现频率」永远不变，玩家体感就是「怎么还是老出这些传奇」。

### 14.2 新机制：动态档位权重

把两步合成**一次全局加权抽取**（`tower.js` 的 `dynamicTierWeights`）：

```
档 r 的实际权重 = baseTier[r] × Σ_{b∈可用(r)} m_b / |可用(r)|      （档内平均倍率）
单件 b 的权重   = baseTier[r] × m_b / |可用(r)|
```

两者等价，而且「某个 buff 的 m_b 下降 → 整档预算按比例缩水 → 省下的概率按比例分给其它档」——
这就是用户口径的动态分配，只是不需要真的把 α,β,γ,δ 重算一遍再归一化。

- `m_b` = **动态惩罚**（`buffDynamicPenaltyOf`：`repeatWeight` 衰减 + `weightDivBy` 份数降权）；
  `TIER_AVG_INCLUDES_STATIC = false`（默认）时**只有**这部分参与档位缩放，
  所以新开一局的分布与旧版**逐位一致**（实测 66.5323 / 21.1694 / 10.0806 / 2.2177）。
  改成 `true` 则静态 `shopWeight`（目前只有 C14 = 0.12）也一起缩放档位。
- 档内没有可用件时该档预算为 0（旧版要「顺延到邻近档」，会把概率整块塞给邻居）。
- 三个抽取口子全部接上：战斗奖励 `rollChoices`、试炼商店 `rollShopSlots`、铸币商店 `rollMintSlots`
  （铸币商店档内仍保留「大概率运营类」的子池偏向）。
- 刷新倾斜 `p^i`、`天命所归`、传奇两档下调仍照旧乘在 `baseTier` 上，**叠加**在动态权重之下。
- 总开关 `TIER_DYNAMIC_WEIGHTS`（默认 `true`）可一键回到旧口径。

修复后的实测（同为 `shopPool`）：

| C37 附魔数 | C37 权重 | C37 全局出率 | 传奇档总概率 |
| --- | --- | --- | --- |
| 0 | ×1 | 0.554% | 2.218% |
| 1 | ÷2 | 0.286% | 2.000% |
| 2 | ÷3 | 0.193% | 1.928% |
| 3 | ÷4 | 0.146% | 1.891% |
| 5 | ÷6 | 0.098% | 1.855% |

> C37 的 `weightDivBy` 配了 `weightDivOffset: 1` → 权重 = `÷(附魔数+1)`。
> 旧口径是 `÷n`（0 与 1 个附魔都是 ×1），导致「第一次附魔完全没感觉」；
> 终焉烙印 C49 保持 `÷n`（它的卡面就写「÷ 份数」）。
