# docs/ 目录规范（给 AI Agent）

> **除非用户明确同意，不要新建任何文档**（本目录、仓库根、或任何子目录都不要）。
> 这是用户反复强调过的口径：文档一多就没人看，最后变成误导。

## 硬性规则

1. **不要新建文档。** 需要记录的内容一律追加到 `更新记录.md`（**最新批次写在最上面**）。
   确实想新建文件时（设计文档、方案对比、README 之类）：先在回复里说明「为什么非新建不可」
   并等用户同意，再动手。
2. **不写过程性文档。** 构建日志、踩坑流水账、实测截图说明、逐轮调参记录 —— 这些属于
   提交信息，最多压缩成 `更新记录.md` 里的 1~3 条要点。
3. **历史提案落地后要收敛。** 旧的设计/建议文档在结论并入代码或 `更新记录.md` 之后，
   原文件删除；细节靠 git 历史与代码注释回溯，不要留"过期但很长"的文件。
4. **`更新记录.md` 是唯一变更日志**，每条写清「改了什么 / 为什么 / 可感知的影响」，
   并按批次标注对应的回归用例名。它是日志、会一直变长，**这是唯一允许长的文件**——
   但每条控制在 1~5 行，别把设计文档整段搬进来。

## 经典 UI 运行约束

改动先按 `js/ssfight/AGENTS.md` 定位公共层，按项目 skill 查询素材与代码。历史的“已修好”记录不能替代当前路径的复核；相似花屏也可能来自数字未填、热区累积、旧挂载或命中列表失效。

- 静态策略通过 `setStaticPolicy({ keepNames, keepIds, blankNames })` 向新实例继承；冻结只停止自播，不把所有元件拨回第一帧。
- 持续装饰动画使用公共白名单；手动动画使用 `holdAnim` / `playOnce`。位图数字空档是末帧；切页时同步填入业务真值。
- 一视图一份播放表。关闭弹层不停止底页，也不靠整页重挂恢复；异步挂载前后都核对请求身份，过期结果只销毁自己。
- 反馈壳、热区与命中逻辑各有公共入口。热区不能把自己的旧扩展框量进画稿；具体契约见取证参考。

现有 `test-ssfight-render.cjs` 运行真实显示层与页面逻辑，但最小 DOM 不验证浏览器字体和视觉观感；需要视觉结论时仍应实际观察。
