# 无尽塔后期平衡：设计方向建议

> 起因（用户口径）：加入大量运营类增益之后，后期很容易进入**极端情况** —— 限次增益几乎全部掏空，
> 玩家只剩「可无限获取」的几件做有限提升，追不上成长越来越快的敌人。
> 本文先用实测数据说明**为什么必然追不上**，再给设计方向与可落地数值。
> 复测工具：`node tools/deep-balance.cjs`（走真实 `Sim.simulate`）。

---

## 0. TL;DR

1. **根因是形状不匹配，不是数值差一点**：敌人 30 层后是**复利**（30→70 层 ×21.7，80 层 ×51，100 层 ×288），
   而玩家可无限获取的成长全是**加法**（C26-C29 各 +20%/+10%）或**线性乘法**（C49 每件 +25%/+50%）。
   两者的相对收益 ∝ `1/累计量`，会**持续衰减**；敌人恒定 +9%/层 → 缺口只会越拉越大。
2. 实测：极端情况下，玩家 farming 10 层后供给/需求 ≈ **1.06**，20 层后 **0.72**，40 层后 **0.44**，60 层后 **0.32**。
   即「追平窗口」只有大约 10 层，之后必败 —— 和体感一致。
3. **收益侧是第二个漏洞**：试炼币收入 **52/层固定**（`COINS.battle 8 × 4 场 + COINS.layer 20`），
   不随层数增长，而难度是复利 → 购买力相对难度指数衰减。
4. **池子结构是第三个漏洞**：无尽池 77 件里只有 **18 件是直接战斗成长**，其中**只有 5 件可无限获取**
   （C26-C29 + C49）；永久槽位 `PERMANENT_SLOTS = 5`，而商店池里有 **45 件 permanent** → 中期之后
   69% 的报价要么"已有"要么"放不下"，商店开始空转。
5. 建议方向（详见 §3）：**D3 敌人曲线解耦 + D4 收益随深度（P0）→ D1 保底乘法通道 + D2 无限件改乘法 + 价格指数（P1）→ D5 溢出转化（P2）**。
   目标：需求斜率从 **+9.1%/层** 降到 ≤ **+6%/层**，供给/需求在 farm 0/20/40 层三点都 ≥ 1.0。

## 1. 实测：需求曲线（玩家要多少倍率才算五五开）

`tools/deep-balance.cjs` 用真实战斗模拟，找「本层第一场胜率 ≥50%」所需的**全属性倍率 X**
（力/敏/速/上限同时 ×X，对照 70 级基准玩家：力 200 / 敏 120 / 速 120 / 血 5000）：

| 层 | 深度乘 `endlessDepthMul` | 需要全属性倍率 | 环比/层 | 敌人 血/力/敏/速 |
| --- | --- | --- | --- | --- |
| 30 | ×1.00 | **×2** | — | 5410 / 192 / 450 / 450 |
| 35 | ×1.40 | ×4 | ×1.149 | 11023 / 442 / 1035 / 1035 |
| 40 | ×1.97 | ×6 | ×1.085 | 16663 / 593 / 1389 / 1389 |
| 45 | ×2.76 | ×8 | ×1.059 | 23371 / 938 / 2196 / 2196 |
| 50 | ×3.87 | ×12 | ×1.085 | 32779 / 1053 / 2464 / 2464 |
| 60 | ×9.16 | ×30 | ×1.096 | 77601 / 2492 / 5833 / 5833 |
| 70 | ×21.69 | **×65** | ×1.080 | 183710 / 5901 / 13810 / 13810 |

- **30→70 层平均 ×1.0909/层（+9.09%）**，即需求是**恒定复利**。
- 需求比 `endlessDepthMul` 还陡一点，因为深度乘**同时乘了四属性**：
  `buildFoe` 里 `stat()`（力/敏/速）与 `heroHp` 都乘 `KM` → 敌人威胁 ≈ `KM²`（血量×输出），
  再叠加行动频率则接近 `KM³`。
- 行动条由速度驱动（`sim.js:1252` `ap += elapsed * effSpeed`）：60 层敌人速度 **5833** vs 玩家 120，
  玩家基本"动一次挨几十下" —— 这是"无法对抗"体感里最刺眼的部分，也是**数值之外**的问题。

**不同基线下的需求**（X = 除已有增益之外**还需要**的全属性倍率）：

| 层 | 裸玩家 | 有限池全拿完（C15 ×1.4 + E07/E08/E11 削敌） | D3 解耦后（属性只吃 √KM + 速度下限） |
| --- | --- | --- | --- |
| 40 | ×6 | ×4 | ×5 |
| 50 | ×12 | ×8 | ×8 |
| 60 | ×30 | ×16 | ×12 |
| 70 | **×65** | **×40** | **×25** |

→ 说明两件事：① 把**有限池全拿完**只把需求压了约 1.6 倍（×65 → ×40），**救不了极端情况**；
② D3 那两条（属性解耦 + 速度下限）**不加任何新成长**就把 40→70 层的需求斜率从
**×1.091/层 降到 ×1.063/层**，且高层"能还手"。

## 2. 实测：供给曲线（极端情况玩家每层能拿到多少）

### 2.1 可无限获取的东西只有 5 件

| 增益 | 稀有度 | 效果 | 形态 |
| --- | --- | --- | --- |
| C26 蛮力 | 普通 | `powerMul +0.20` | 加法，可无限叠 |
| C27 灵巧 | 普通 | `agilityMul +0.20` | 加法 |
| C28 疾行 | 普通 | `speedMul +0.20` | 加法 |
| C29 体质 | 普通 | `maxHpMul +0.10` | 加法 |
| C49 终焉烙印 | 传奇 | 终乘 `+0.25/存活`、`+0.50/损毁`（线性加算） | 线性乘法，无上限 |

（另有 C37 虚空铭文 = 空出 1 个永久槽、C52 回血、E07/E08/E11 一次性削弱、E14 商店半价，都不是直接成长。）

### 2.2 池子结构：77 件里只有 18 件是战斗成长

| 类别 | 件数 | 说明 |
| --- | --- | --- |
| 直接战斗成长 | 9 | C01、C02、C21、C23、C26∞、C27∞、C28∞、C29∞、C15 |
| 烙印（战斗成长） | 9 | C39-C44（各 1 份）、C49∞、C52、C53 |
| **机制 / 生存 / 减伤** | **53** | 占 69% |
| 运营 / 经济 | 6 | C50、E04、C36、C37、C58、C59 |

- 商店池 65 件：普通 17 / 稀有 22 / 史诗 21 / 传奇 5；**普通档里的无限成长件只有 4 件（C26-C29）**。
- 档位权重 66.5/21.2/10.1/2.2 → **每页 5 格期望只出 0.78 件可无限成长件**（且一页内不重复）。
- **永久槽位只有 5 个**（`PERMANENT_SLOTS`），而 `permanent` 类增益有 45 件；
  C26-C29 自身就要占 4 个槽 → 与 C15（×1.4）、C21（暴击）、C14（涅槃）、C37（附魔）**直接抢槽**。
  中期之后商店 5 格里"能买且有意义"的通常 ≤1 件。

### 2.3 收支：收入固定，难度复利

| 项 | 数值 |
| --- | --- |
| 每层试炼币收入 | `COINS.battle 8 × 4 场 + COINS.layer 20` = **52**（x10 层 +15 精英），**不随层数增长** |
| 商店价格 | 普通 30 / 稀有 60 / 史诗 100 / 传奇 160（跨层类 ×1.3） |
| 每层最多购买 | **1.73 件普通**（全部钱都用来买普通件） |
| 刷新价 | 10 → +10，封顶 70（≈ 2.3 件普通的价格） |
| C49 保底节流 | 每 120 格（≈5.7 层）一次 × 2/3 ≈ **0.117 件/层** |

### 2.4 供给 vs 需求：追平窗口只有约 10 层

| 已 farming 层数 | 累计成长件（Σ） | C49 累计 | 加法通道 | 终乘通道 | 合计 | **供给÷需求** |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 0 件（Σ+0.00） | 0 | +15.65% | +4.38% | +20.03% | 2.20 |
| 10 | 7.8 件（Σ+1.37） | 1.2 | +6.61% | +3.04% | +9.65% | **1.06** |
| 20 | 15.7 件（Σ+2.74） | 2.3 | +4.19% | +2.33% | +6.52% | **0.72** |
| 30 | 23.5 件（Σ+4.11） | 3.5 | +3.06% | +1.89% | +4.96% | 0.55 |
| 40 | 31.3 件（Σ+5.48） | 4.7 | +2.42% | +1.59% | +4.01% | 0.44 |
| 60 | 47.0 件（Σ+8.22） | 7.0 | +1.70% | +1.21% | +2.91% | **0.32** |

> 这是**乐观假设**（假设每页 0.78 件成长件全部买得起、且全部转化为成长）。
> 真实情况更差：钱不够、报价被已拥有的件占满、槽位放不下。

### 2.5 换算：加法与乘法的差距

| 第 70 层要 ×65 的全属性 | 需要件数 | 按当前出现率（≈0.2 件/层的 C26）需要 |
| --- | --- | --- |
| C26「+20% **加法**」 | **320 件** | ≈ 1635 层 |
| 若改成「每次 **×1.15 乘法**」 | **30 件** | ≈ 150 层（且与别的通道同步受益） |

**这就是根因**：加法每件贡献固定的绝对值，相对收益 ∝1/累计量；
复利敌人的相对增长恒定 → 数学上必然发散。

## 3. 设计方向

### D1 深度成长通道（保底乘法）—— 推荐，最直接解决"形状"

**现状**：30 层之后玩家没有任何"跟着层数走"的成长，全靠商店运气。

**建议**：新增一条**只在本局生效**的乘法通道，与 `endlessDepthMul` 对称：

```js
// tower-data.js
const DEPTH_GROWTH_RATE = 0.045;      // 每层 +4.5%（全属性乘法）
function endlessDepthGrowth(layer) { return Math.pow(1 + DEPTH_GROWTH_RATE, Math.max(0, layer - 30)); }
// tower.js adjustMe：与 globalMul 同层，最后乘
const dg = TD.endlessDepthGrowth(run.layer);
me.power = Math.round(me.power * dg); /* 敏/速/上限同理 */
```

- 为什么 4.5%：需求是 +9.1%/层，其中约一半由"D1 保底"兜住，剩下一半交给运营/构筑（保留"练度决定高度"）。
- 70 层时 `1.045^40 = ×5.82`；配合 D3 降斜率（需求 ×25 → 约 ×1.05/层）后，D1 一个人就能兜住大半。
- **副作用**：会让"混到 40 层"更容易，所以必须与 D3 的斜率调整一起上，不能单独上。
- 30 层前完全不受影响（`max(0, layer-30)`）。
- **验收**：70 层第一场胜率 45%~55%（现在 0%）。

### D2 无限成长件从「加法」改成「乘法 + 价格指数」—— 推荐，给运营留出上限

**现状**：C26-C29 是加法，买第 50 件几乎等于没买。

**建议**：新增 `powerTimes` 乘区（每次 ×1.15），价格按已购份数指数上涨：

```js
// 数据：C26 → { powerTimes: 1.15 }（C29 → maxHpTimes: 1.10）
// 生效：me.power = Math.round(me.power * Math.pow(1.15, stacks))
// 定价：price = 30 * Math.pow(1.12, 已购份数)      // 1.12 温和，1.18 更硬
```

| 价格指数 | 每层可买（收入 52，D4 前） | 每层相对成长 | 能否追上 +9.1% |
| --- | --- | --- | --- |
| 1.12 | ≈0.5 件 | `1.15^0.5` ≈ **+7.2%** | 接近（配合 D1/D3 够） |
| 1.18 | ≈0.3 件 | `1.15^0.3` ≈ +4.3% | 不够，需 D1 补 |

- 好处：**相对收益恒定**，与敌人复利同形；价格指数天然限制了"无损滚雪球"。
- 副作用：早期也会变强 → 建议**只在 30 层后启用乘法**，或把这四件移到史诗档、深层才进池。
- **验收**：每层有效购买 ≥2 件；深层玩家属性曲线斜率 ≥ +6%/层。

### D3 敌人曲线解耦 + 速度下限 —— P0，改动最小、手感提升最大

**现状**：`KM` 同时乘血/力/敏/速，且 50 层后斜率还从 7% 提到 9%。

**建议（三选，建议全做）**：

1. **属性与血量解耦**：血量吃满 `KM`，力量/敏捷/速度只吃 `KM^0.5`
   （`buildFoe` 里 `stat()` 用 `Math.sqrt(KM)`，`heroHp` 用 `KM`）。
   70 层：血量仍 ×21.7，属性只 ×4.66。
2. **速度下限**：战斗内 `me.speed = max(me.speed, foe.speed * 0.55)`（只影响行动条，不改面板）。
   保证玩家至少每两回合能行动一次，消灭"动一次挨几十下"。
3. **斜率略降**：`ENDLESS_DEEP_RATE1 0.07 → 0.055`、`RATE2 0.09 → 0.07`
   → `KM`：70 层 ×21.7 → **×11.3**，80 层 ×51.3 → **×22.2**，100 层 ×288 → **×86**。

**实测（只做 1+2，还没动斜率）**：有限池基线下的 70 层需求 **×40 → ×25**，
40→70 层斜率 **×1.0909/层 → ×1.0630/层**；再叠加第 3 条预计能到 ≤ ×1.05/层。
（复测命令：见 §5；上面四个数字都可以用 `deep-balance.cjs` 的同一套判定重跑。）

- **验收**：`deep-balance.cjs` 的需求斜率从 +9.09%/层 降到 ≤ **+6%/层**。

### D4 收益随深度增长 —— P0，堵住第二个漏洞

**现状**：`COINS = { battle: 8, layer: 20, elite: 15 }` 固定，难度却是复利 → 购买力指数衰减。

**建议**：

```js
function coinDepthMul(layer) { return Math.pow(1.05, Math.max(0, layer - 30)); }  // 70 层 ×7.0
// run.coins += Math.round(COINS.battle * coinMul * coinDepthMul(layer));
// 层奖励同理
```

- 与 D2 的价格指数配合：收入 ×1.05/层 vs 价格 ×1.12/件 → 每层仍能买 ~0.5 件，但**不至于越打越穷**。
- 若不想动币值，替代方案：深层掉落**「深潜结晶」**（只用于买乘法成长件），与普通币分开计价。
- **验收**：到 70 层时每层仍能买 ≥2 件普通件。

### D5 溢出转化：把"掏空的池子"变成燃料 —— P2，体验层

**现状**：`ownable` 会把"已拥有且不可再叠"的件从池里过滤掉；永久槽只有 5 个 →
后期一页 5 格里往往只有 1 件可用，刷新一次（10~70 币）也不一定能刷到东西，体验是"空转"。

**建议**：当一格滚出"已拥有且不可再叠"或"永久槽已满"的件时，**自动转化为「虚空结晶」**：

```
普通 +1 / 稀有 +2 / 史诗 +3 / 传奇 +5 结晶
1 结晶 = 该件稀有度对应的**乘法**成长（例如：1 结晶 = 全属性 ×1.02，可无限叠）
```

- 效果：每一页都有下限收益，商店不再空转；同时把"运营类/机制类"的冗余转化为后期燃料。
- 与已有的 `sacrifice`（献祭）机制同一个方向，可以合并成"后期三选一：买 / 献祭 / 转化"。
- **验收**：70 层时"一页 ≥1 件有意义的事"的概率 ≥ 90%。

### D6 运营类增益的后期出口 —— P2，配套

| 增益 | 现状 | 建议 |
| --- | --- | --- |
| C58 豪掷千金 | 每 100 币 → 随机限次增益 | 限次池掏空后失效 → 改成"→ 虚空结晶 ×2" |
| C36 挥金如土 | 每 5 币 → 属性（已改一局一次） | 可作为"结晶转化器"的载体（每 N 币 → 1 结晶） |
| E04 steam 大促 | 30% 折扣 | 深层无意义 → 折扣可叠加"深层倍率" |
| C50 抉择扩充 | +1 选择张数 | 仍是有效件，保留 |
| C37 虚空铭文 | 空出永久槽 | 后期槽位不缺时会失效 → 可改成"槽位 → 乘法成长"的转化器 |

## 4. 推荐组合与优先级

| 优先级 | 改动 | 预期效果 | 风险 |
| --- | --- | --- | --- |
| **P0** | D3（属性解耦 + 速度下限 + 斜率）| 需求斜率 9.1% → ~6%；高层"能还手" | 老平衡（≤30 层）不受影响；需重测 30-50 层 |
| **P0** | D4（收益 ×1.05/层） | 购买力不再指数衰减 | 需要同步调 D2 的价格指数 |
| **P1** | D1（深度成长 ×1.045/层）| 提供"保底曲线"，缺口不再发散 | 单独上会偏简单，必须配 D3 |
| **P1** | D2（无限件改乘法 + 价格指数）| 相对收益恒定，运营技巧有上限 | 早期变强 → 限定 30 层后 / 深层进池 |
| **P2** | D5（溢出转化 → 结晶）| 后期商店不空转 | 需要新 UI 与文案 |
| **P2** | D6（运营件转结晶）| 运营类在后期仍有用 | 同上 |

**不建议**：只把 `endlessDepthMul` 的系数调小。
它只把"撞墙点"往后挪 10~20 层，**形状**（复利 vs 线性）没变，玩家迟早还是必败，
而且会一起牺牲前期难度手感。

```bash
node tools/deep-balance.cjs            # 需求曲线 + 供给/需求比
```

| --- | --- | --- |
| 需求斜率（30→70 层） | **+9.09%/层** | ≤ **+6%/层** |
