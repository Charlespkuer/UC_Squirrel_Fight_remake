## 2026-10-23 第三百四十九批：去掉无尽塔胜利后的「战斗拾取」空弹窗

- **根因**（`js/main.js` / `js/classic-ui.js`）：现代界面每场非经典战斗结束后都会调
  `UI.classic.pickupResult(loot, finalReward, winner)`；两座塔是 `collectDrops:false`、也没有
  `rewardFor`，收益是空的，但 `winner === 0` 让 `pickupResult` 的旧守卫放行，于是弹出一个只有
  「战斗拾取 / 胜利！ / 确定」的空窗（用户 2026-10 截图）。塔的产出本来就由
  `Tower.reportBattle` 结算，不该再盖这一层。
- **实现**：`main.js` 对 `opts.kind === 'tower' || 'endless'` 跳过 `pickupResult`；同时把
  `pickupResult` 的守卫改成「拾取物 / 升级 / 战斗奖励三者全空就不弹」——胜负大字只是收益弹窗的
  抬头，不是单独开窗的理由。塔的升级奖励仍通过 `ups` 这个非空口子展示。
- **回归**：`test-ssfight-render.cjs` 的收益弹窗一节加两条断言（塔战跳过 pickupResult、空收益不弹窗）；
  无头 Chrome 用 E17「假如我直接赢」在无尽塔赢下一场，9 秒后无任何「战斗拾取」弹窗；
  直接调 `pickupResult({}, null, 0)` 无弹窗，传 `reward` 时仍正常弹「战斗结算」。

## 2026-10-23 第三百四十七批：无尽塔五场层（四雄）的第 5 张头像不再盖住「继续战斗」

- **根因**（`js/tower-ui.js` / `css/tower.css`）：60/70/80/90 层的最后一战是四雄，整列有 **5 张**对手卡；
  右下角「继续战斗 / 放弃本局」是固定定位，第 5 张卡（四雄头像）正好压在按钮上，按钮看不见也点不到。
  上一批加的 `.tower-page.endless-page .tower-main { padding-bottom: 190px; }` 与
  `.endless-page .endless-actions { z-index: 60; }` 因为**页面从没挂 `endless-page`** 一直是死规则；
  经典外壳的 92×80 卡片更会把最后一张压到按钮底下。用户口径「四雄完全没有对齐头像与战斗内ui」即此。
- **实现**：局内正常棋盘（有动作条）才挂 `endless-page`，并把对手数 ≥5 时挂 `foes-many`：
  现代版把 5 张卡从货币条下方起排、立绘收到 84×66、行距收紧，第 5 张底边停在按钮上方；
  经典壳另加 `foes-many` 覆盖（立绘 80×68、卡片内边距/行距收紧）。动作条 z-index 仍抬到对手列之上，
  窄高窗口滚动时也不会被卡片挡住。
- **素材/战斗不变**：四雄头像与战斗内仍走经典 `6833`（按 `mcFrame` 取狡兔/狼王/妖狐/猿将），
  这次只修预告列与动作条的占位，不改模型、数值或战斗渲染器。
- **回归**：`test-campaign-boss.cjs` 新增「endless-page / foes-many 接线 + 两张 CSS 压缩规则」与
  「四雄头像与战斗内同一 id / 同一 mcFrame」用例（9/9 通过）；无头 Chrome 实测 60/70/80/90 现代版第 5 张卡底边 588、按钮顶边 591，
  点击按钮中心命中 `[data-action="fight"]` 并正常进入 `暗御猿将` 经典战斗；经典村庄壳同样无重叠；
  4 张卡的 91 层不受影响。资源路径与编码检查通过。
