# 无尽塔剧情触发条件（应当条件 · 逐条对照实测）

> 这份文档是**用户要求**写的（2026-10：「写一个剧情触发的应当条件文档，并与实际测试进行对照」），
> 所以它属于「用户点名要的文档」，不是随手新增的设计稿。
>
> 口径：左边是**应当条件**（代码里怎么判、什么时候必须播、什么时候绝不能播），
> 右边是**实测对照**（哪条回归用例 / 哪个探针在盯它）。
> 改剧情、改触发时机时，**先改这张表，再改代码与用例**；对不上的地方就是 bug。
>
> 相关实现：文本与播片机在 `js/tower-plot.js`（`STORY_SCRIPTS` / `pending` / `due` / `storyFinish`），
> 「什么时候挂待播」在 `js/tower.js`（`noteEntryStory` / `autoPlayStory` / `noteXxxStory` /
> `clearRunStory*`），渲染在 `js/tower-ui.js` 的 `openEndless`。
> 回归：`tools/test-mint-shop.cjs`（第 14~16 组）、`tools/test-env-buff.cjs`（主线剧情一组）；
> 全流程核对用 `out/bot-story.cjs`（玩家机器人，爬 1→200+ 层逐条断言，本地工具、不进仓库）。

## 勇者模式的际遇选择

勇者际遇由 Tower.heroEventInfo / resolveHeroEvent 管理，是带局内奖励的选择界面，独立于下列 TowerPlot 播片开关。关闭旧剧情不会跳过勇者的玩法选择。每次先展示一个未完成际遇，再继续原有商店、场间抉择与剧情；选择记录在 run.hero.events，随存档与战斗回滚保存。

- **不再有 departure**：开局没有 60 试炼币，勇者直接进入第一场战斗。
- **首次巡逻胜利**不再触发 forge，而是由状态机**固定发放「渴血之剑」**（替代该场传奇三选一，不可跳过）；**第一次自然刷出铸币商店**时改为触发授业（mentor），此后按 25 胜与 41/80 层触发营火、巡镜者与钟声之前。旧的「断锋归鞘」事件已移除。
- 整百层胜利不再有 ascension-N 事件；下一轮的 cycle-N 仍按本局轮次触发，不替代原魔王三连战的剧情闸门。
- 每个选择按「事件id:选项id」校验，已完成或过期选项不能再领奖。战斗中不发事件；未完成事件前不可直接开始下一战。
- 勇者际遇与剧情模式共用 `.tower-story` 整屏界面（`TowerPlot.eventHtml`），不再另做事件卡；文本已重写为阶前的盲眼师 / 倒燃的营火 / 巡镜者 / 钟声之前 / 镜外的新雪。
- **渴血之剑**由第一次巡视胜利固定获得（默认与勇者剧本都成立），不进随机池、不可出售 / 交换；初始在限次区，用尽进化、最终为王者之剑。获取 / 强制苏醒 / 彻底失活三段剧情走 `storyQueue`（当前剧情播完再接），见第 2 节。
- 专项回归在 tools/test-tower-hero.cjs 与 tools/test-blood-blade.cjs；不修改默认模式原有的剧情条件。

### 勇者剧本的剧情文本变体

- `TowerPlot.SCRIPTS` 的 **46 段**在勇者对局下全部改用 `TowerPlot.HERO_SCRIPTS` 中的同名文本（开场、商人、巡视、层间主线、整百层、四雄与渴血之剑全部覆盖）；**id / once / 触发条件一律沿用默认表**，只换文字，不改播片时机。
- 勇者局的「只播一次」记账用 **`hero:<id>`**（默认局仍用 `<id>`），所以先玩默认模式、再开勇者剧本时，勇者的开场 / 商店 / 巡视 / 层间主线不会被默认局的 `storySeen` 吞掉。
- 分流判据是 `Tower.heroRunActive()`（当前 `endless().run.ruleset === 'hero'`），`storyScript()` 自动取勇者文本；默认剧本仍走原来的 `STORY_SCRIPTS`。
- 勇者际遇只允许 `TowerPlot.eventHtml()` 的 `.tower-story` 模板；`tower-ui` 里那张非剧情模板的「事件卡」兜底已删除。
- 回归：`test-tower-hero`（46 段全覆盖、开场 / 商店 / 巡视与默认文本不同、事件卡已移除、eventHtml 使用剧情模板）；默认剧情的触发回归仍看 `test-mint-shop` 第 14~17 组与 `test-env-buff`。

## 0. 三条总闸（以下 TowerPlot 节点均受约束）

| 应当条件 | 说明 | 实测对照 |
|---|---|---|
| **挑战模式（`storyEnabled()` 为假）下一律不播** | 存档 `endless().storyOn === false` 时 `pending()` / `due()` 直接返回 null | `test-mint-shop.cjs` 第 14 组「挑战模式下起局 / 进店都不播剧情」 |
| **「只播一次」的记账必须跟着存档走（跨局永久）** | `endless().storySeen` 是**跨局**的账（第一次遇商人 / 第一次失去烙印 / 第一次遇巡视…）。⚠️ **往 `endless()` 上加任何「已经播过 / 已经给过」的字段时，必须同时加进 `js/state.js` 的 `normalizeSave` 白名单** —— 那份白名单是显式的，没列到的字段**重载即清零**：2026-10 用户实测就是「无尽塔玩到一半退出游戏再重进，商店 / 烙印 / 巡视全变回第一次的文案」（`storySeen` 与 `storyOn` 当时都没在白名单里）。`run.*` 上的记账（`patrolStoryAt` / `x00PreNo` / …）随对局整体存，不受影响 | `test-state.cjs`「存档往返：剧情『只播一次』的记账与剧情模式开关必须保留」 |
| **一屏只播一段，播完按顺序接下一段** | 一段播完先 `clearRunStoryPending`（清「延迟一步」的槽），再问 `nextEntryStoryOf()`（整百层连播链），否则 `clearRunStory` | 第 15/16 组；机器人「同一段不重播」断言 |
| **「战斗之前」的剧情不得在战后阶段补播** | `due()` 在 `run.phase`（商店 / 结算 / 献祭 / 收缴 / 镜中世界）或「本层已清空」时不返回 | 第 15 组；机器人「第 1 场之前必须已播」断言 |

## 2. 按事件触发

| 剧情 | 应当在什么时候播 | 关键判据 | 实测对照 |
|---|---|---|---|
| `layer31` 第一次失烙印 | **烙印真的碎了**那一次：先出「烙印失效」停留提示屏，点掉之后播剧情 | 事件埋点（`applyBrokenMarkLoss` → `noteFirstMarkLostStory`），不是层号；只一次；**播完必须清掉待播槽**，否则会反复重播（第 100 层连播时必现） | 第 15 组「挪层不动计数」；本批新增的机器人「一度播两次」断言 |
| `gate20b` 天平·珍宝 | 第 20 层清完、**离开商店之后、弹献祭窗之前** | 轮内层号 ≤ 20 的兜底（30 层之后不再重播这段） | 第 15 组「献祭文案」 |
| `gate20c` 石门开启 | 献祭**完成**之后，进第 21 层之前 | 只一次 | 第 15 组 |
| `offer1`~`offer5` | 此后每 10 层的献祭之前，**随机**一段 | 每次都播（不记 seen） | 第 15 组「30 层走随机供词」 |
| `patrolGate` 首次巡视 | **第一次**路上偶遇巡视：**那一场战斗之前**（`run.idx` 指着它，不是进层就播） | 全局只一次 | 第 15 组（重写后）；机器人「巡视那一场之前 `patrolStoryAt` 已记」断言 |
| `patrolMeet` / `patrolMeet2`…`8` | 之后每次偶遇：那一场之前播一段，编号递增；**8 段讲完从头再讲一轮** | 段号记在**本局**（`run.patrolMeetNo`，按 1~8 循环）；**一次偶遇只讲一段**；绝不能固定返回同一段、也不能讲完就静默 | 第 15 组「一次偶遇一段 + 读完必定能开打 + 一轮讲完从头再讲」 |
| `patrolFailA` 巡视失败（交纳前） | 巡视**败北**结算时立刻播，之后才弹收缴窗 | 每次都播 | 机器人日志；`test-mint-shop` 巡逻收缴相关用例 |
| `patrolFailB` 交纳之后 | 玩家交出藏品（`payPatrolToll`）之后播 | 判据是**本局记的 `run.patrolFailStoryAt`**（那两段是 `once:false`，用 seen 判会永远不播） | 机器人「`patrolFailA` 之后必须出现 `patrolFailB`」断言 |
| `patrolWin` 巡视胜利 | 巡视**胜利**结算时播，**包括它是本层最后一场**的情况 | 本层最后一场的巡逻不能因为「层已清空」提前 return 而丢掉这段与传奇奖励 | 机器人「巡逻胜利必播」断言 |
| `bladeGet` 渴血之剑 | **第一次**巡视胜利结算时（`grantBlade`）排队；若同一场还有 `patrolWin`，等它播完由 `storyQueue` 接上 | 只一次；不是可选奖励，不读 `storySeen` 以外的条件 | `test-blood-blade` 首次巡视 / 勇者模式两例 |
| `bladeForce` 强制苏醒 | 剑被关闭并累计闲置满 **20 场**后的那一场胜利结算时排队 | 每次都播（`once:false`）；玩家不能拒绝，剑自动开启 | `test-blood-blade`「闲置 20 场强制苏醒」 |
| `bladeDead` 彻底失活 | 活性事件里**连续抑制第 3 次**时排队 | 只一次；之后剑变涸血之剑，不再有活性事件 | `test-blood-blade`「连续抑制 3 次 → 涸血之剑」 |

> 51 / 61 / 71… 层的「活性」事件是**弹窗选择**（抑制 / 增强），不是 `TowerPlot` 播片：`run.bladeEventPending` 与 `run.bladeSacrificePending` 都是必选状态，`nextBattle` 会拒绝开战；读档后由 `openEndless` 重新弹同一个窗。献祭窗同样没有关闭叉，祭品列表见 `Tower.bladeSacrificeCandidates()`。

## 3. 整百层「觐见魔王」的连播链（顺序固定 · **每次到达整百层都讲一遍**）

| 顺序 | 剧情 | 应当在什么时候播 |
|---|---|---|
| 1 | `layer100` 王庭 | 第 1 场**之前**（`x00PreNo` 0 → 1） |
| 2 | `x00a` 第一近卫 | 第 1 场**之前**，紧接上一段（`x00PreNo` 1 → 2） |
| 3 | `x00b` 第二近卫 | 第 1 场**之后**、第 2 场**之前**（`x00stage` 2） |
| 4 | `x00c` 三重王命 | 第 2 场**之后**、第 3 场**之前**（`x00stage` 3） |
| 5 | `x00win` 终章 | 第 3 场（魔王）**之后**（`x00stage` 4） |
| 6 | 【U20】照影之境拾取屏 | 终章之后、**「继续挑战」之前**（不是剧情，但属于同一条链） |

- **进度记账**：`run.x00PreNo`（前两段，进整百层归零）与 `run.x00stage`（五段的段号，进整百层归零）
  都是「**这一层**」的记账 —— 换层 / 挪层就重来，所以在第 200 / 300 层会再讲一遍
  （与「照影之境每 100 层叠一层」同一个节奏）。
- 实测对照：`test-mint-shop.cjs` 第 16 组（终章 → 拾取屏 → 101 层）、
  `out/probe-x00-cycle.cjs`（第 200 层：五段全部重讲一遍 + 照影叠到 2 层）、
  机器人「第 2 / 3 场之前 x00b / x00c 已播、打完第 3 场 x00win 已播」断言。
- ⚠ 这条链最容易被四类问题破坏，回归里都必须盯住：
  ① **待播槽没被消费**（`pendingStory` / `run.story` 残留 → 排在后面那一段前面 → 反复重播）；
  ② **`run.idx` 在归一化时被夹回**（`normalizeRun` 的坏档兜底会把 `idx` 夹到 `plan.length-1`，
  于是「本层是否已清空」永远判不出来 —— 整百层打完魔王卡在第 100 层）；
  ③ **同一时刻只有一个待播槽**：战斗结算的剧情与新层的入场剧情撞车时，
  必须「先挂战斗那一段（在 `layerClear` 之前），新层那两段由连播接力在它播完之后接上」——
  反过来的话新挂的入场剧情会被结算剧情直接**顶掉**（本批实测踩到过：本层最后一场是巡逻且赢了）。
  ④ **拿存档 seen 表判「该不该讲」**（旧口径）→ 第二次到达整百层就整段不播。

## 5. 「不该播」的检查清单（回归里逐条盯）

1. 挑战模式下**一段都不播**。
2. 「只播一次」的段**播两次**即是 bug（机器人按 `TowerPlot.begin` 的调用序列断言）。
3. 已播过的入场剧情**不再播**（`storySeen`）。
4. 本层第 1 场已经打过的存档，**不得**在商店 / 献祭 / 结算点那一屏补播入场剧情。
5. 剧情屏上**不得**再叠弹窗（献祭窗由 `TowerPlot.showing()` 让路；里程碑奖励也改成剧情播完再弹）。
6. 战斗开打前的最后一道闸：`Tower.storyPendingForBattle` 为真时**不能开打**
   （用无副作用的纯查询，别建战斗令牌）。

**本批（对照本表跑出来的）修掉的 6 处**：

1. **整百层那两段第二次不播**（用户报的「第 100 层又有概率吞掉那两段」）：
   原来拿 `storySeen` 判「该不该讲」→ 上一局看过、或从 101 层挪回 100 层就整段不播。
   现在按 `run.x00PreNo`（**每次到达整百层**重新讲一遍），并给 `x00stage` 在进整百层时归零。
2. **巡视段号走完 8 段之后彻底静默**（机器人实测：第 163 层之后再没播过巡视剧情）：
   原来是「讲完就返回 null 放行」—— 短局看不出来，长局里就是「巡视剧情被吞掉」。
   现在段号在 1~8 之间**循环**（每次偶遇仍然只讲一段、绝不重复触发同一段）。
3. **本层最后一场是巡逻且赢了时**：`patrolWin` 剧情与传奇三选一被「层已清空」那条提前 return 吞掉。
4. **`patrolFailB`（魔王接过藏品那一段）从来没播过**：判据写的是
   `storySeen('patrolFailA')`，而那两段是 `once:false`、永远不写 seen 表 → 改成本局记账
   `run.patrolFailStoryAt`。
5. **整层最后一场挂 E01「立即进货」时崩溃**：`makeShop` 在整百层（不开店）返回 null，
   代码却直接 `null.postBattle = true` → 抛异常打断 `reportBattle`（界面停在战斗屏）。
6. **选取型强化的弹窗死循环**（机器人跑出来的软锁，与剧情同属「卡死界面」那一类）：
   没有武器时「神兵淬炼」、只剩 `noExtend` 的限益时「延续铭文」都会挂一个 **0 候选**的
   `pendingPick` —— 弹窗点不掉、也走不了。现在这两类也走「先替你留着」（`deferredPicks`），
   `hasPickTargets` 与候选列表同口径（`noExtend` 一起排除）。
