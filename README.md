# 松鼠大战 · 怀旧单机复刻版

把当年 UC 乐园《松鼠大战》的玩法做成**纯静态网页**的单机复刻：三侠闯关、背包装备、
装备融合、竞技场天梯、师徒好友、挑战塔与无尽塔。没有构建步骤，双击启动器就能玩；
存档写本地文件，也支持 Mac ↔ Windows 双机同步。

## 启动

| 平台 | 方式 |
|---|---|
| macOS | 双击 `启动游戏.command`（停止：`bash 启动游戏.command --stop`） |
| Windows | 双击 `启动游戏.cmd` |
| 手动 | `node scripts/serve.js` → 浏览器打开 `http://127.0.0.1:8080/` |

存档默认写在 `save/progress.json`（磁盘优先，浏览器 localStorage 只是兜底）；
启动时会自动体检存档，损坏时从 `save/backup/` 恢复快照。
直接静态托管也能玩，但存档只留在浏览器里，双机同步不可用。

## 玩法

- **关卡**：18 关推进，每关三名对手 + 关底 Boss。
- **战斗**：经典 1170×690 画布；普攻 / 技能 / 道具，暴击、闪避、吸血、反伤、
  护盾、中毒、复活等机制。实战与离线模拟共用同一套规则。
- **成长**：升级给属性点与礼包，武器 / 技能三选一，经验丸与属性丸等道具。
- **背包与装备**：部位 × 品质（普通 → 稀有 → 史诗 → 传奇），强化、镶嵌、天赋与武技。
- **装备融合**：同部位同品质三件合成更高品质一件。
- **竞技场与天梯**：经验场、碎片场、天梯赛（积分 / 金杯 / 周榜）。
- **师徒与好友**：拜师收徒领贡品，好友切磋与随机挑战。
- **挑战塔**：每层一张挑战书，连战只继承血量，层间三选一增益。
- **无尽挑战塔**：免门票从 1 层冲分；限次 / 永久 / 即时三类增益、段位轮转机制、
  每 5 层试炼商店、**x2~x4 / x7~x9 层按 `mintChance` 概率刷出的铸币商店（5%→10%，每 5 层 +0.5%）**、每 10 层里程碑奖励，随时可结算离场。
- **双机同步**：Mac ↔ Windows 通过 ZeroTier 互推存档与游戏文件（`scripts/一键同步`）。

## 三侠削弱重做：按大招实际命中累加 + 数值浮动 + 本层上限（2026-10）

**以前**：三侠的大招只要「放出来」就给玩家留一条**固定数值**的削弱，而且同一位大侠每层只落一次 ——
命中几次、打没打中都不影响。

**现在**（用户口径）：

1. **只算真的打到玩家的那几次大招** —— 从这一场的战斗报告里逐条核对：
   被**闪避**（`dodge`）、被**弹反**（`jueDui` / `reboundHurt`，绝对防御这类把伤害弹回去的）、
   被**装死**（`fakeDie`）挡掉，或者**没造成伤害**（护盾全吸收 / 格挡到 0，`dmg = 0`）的那几次**都不计入**。
   （这条能成立，靠的是前一轮修好的「界面把战斗报告 `result` 传给 `reportBattle`」。）
2. **按命中次数逐次累加**，而且**数值随机浮动**：

| 大侠 | 削弱 | 每次命中 | 本层上限 |
|---|---|---|---|
| 螳螂大侠 | **重伤**（生命上限） | 随机 **−3%~6%** | **累计最多 −15%**（多层相乘，按 `1−Π(1−p)` 算，余量不足 1% 就不再落条目） |
| 仙鹤大侠 | **战吼**（随机属性） | 每次随机削 **力/敏/速** 一项 **−5%~10%** | **最多 3 次** |
| 熊猫大侠 | **压制**（锁武技） | 每次随机锁一把武器 / 一个技能（**不与已锁的重复**） | **最多 2 个** |

3. 换层照旧由 `advanceLayer` 清空（「贯穿本层」）；**同一位大侠在一层里可以同时有多条削弱** ——
   幻影回响 / 时间回廊 E15 会把同一场再打一次，命中越多削得越狠，直到吃满上限。

顺手修掉一个自己前一版留下的坑：`normalizeRun` 里那条「按来源去重」会把新落的多条削弱合并成 1 条
（当时是为了清跨层残留，现在与「逐次累加」冲突），已删掉 —— 跨层残留本来就由 `advanceLayer` 负责清。

回归守卫 **需求94**：命中判定（闪避 / 弹反 / 装死 / 0 伤害各自单独验一遍都不落条目）、
螳螂的浮动区间与 15% 累计上限（8 次命中后条数 3~5、总量 ≤15% 且接近 15%）、
仙鹤 3 次封顶与 5%~10% 区间、熊猫 2 个封顶且不重复锁同一件（并用 `adjustMe` 验证真的少了 2 件）、
换层清空；`需求91`（每层口径）也同步改成「带伤害的大招事件」才落削弱。

## 平衡调整：立即进货 / 虚空铭文 / 门庭若市 / 商店刷新 / 豪掷千金（2026-10）

| 项目 | 改动 | 理由 |
|---|---|---|
| **立即进货（E01）** | 稀有度 **稀有 → 史诗**；折扣 **−50% → −30%（7 折）**，与 steam大促 同档 | 5 折的战后商店太便宜；两券同持仍是 **3.5 折**（合并值 0.65 没被更小的单券折扣压掉 —— 顺手修了这个退化） |
| **虚空铭文（C37）** | `mods.weightDivBy = 'enchanted'`：**weight = 初始 ÷ 已附魔数量**（0~1 个 → ×1、2 个 → ÷2、3 个 → ÷3、5 个 → ÷5） | 附魔越多越难再刷到它；公式由用户指定为 x/n，比上一版的「每份 ×0.5」温和 |
| **终焉烙印（C49）** | `mods.weightDivBy = 'owned'`：**weight = 初始 ÷ 身上份数**（含碎掉的烙印）；**替代**原来的 `repeatWeight: 0.10` | 原来 1/2/3 份 → ×1 / ×0.1 / ×0.01，第 2、3 份几乎刷不到；现在与虚空铭文同一套口径 |
| **门庭若市（C59）** | 每次进店 **100 → 80 试炼币**（×层数，可叠 3 层） | 进店白拿的钱太肥 |
| **商店刷新** | 价格上限 **50 → 70**；但**稀有度收益仍在 50 那一档封顶**（`SHOP.rerollTiltCap = 50`） | 价格可以继续涨（多一个「要不要再刷」的取舍），但质量不再无限上升；界面会写「已到收益上限（50 币那一档封顶）」 |
| **豪掷千金（C58）** | 新增 `mods.limitedRarityMul = [1, 1, 0.5, 0.35]`：抽随机限次增益时**史诗 ×0.5、传奇 ×0.35** | 原来等权重抽，史诗及以上拿得太容易 |

「份数越多越难再出现」现在是**一套统一口径**（`mods.weightDivBy`）：

```js
weight = 初始 weight ÷ n          // n ≤ 1 时不降
// 'enchanted' → n = 本局被虚空铭文附魔过的永久增益数量（C37）
// 'owned'     → n = 本局已获得的份数（含碎掉的烙印，C49）
```

实测（相对初始权重）：C37 `0→1.000  1→1.000  2→0.500  3→0.333  5→0.200`；
C49 `0→1.000  1→1.000  2→0.500  3→0.333  4→0.250`（旧口径是 `1 / 0.1 / 0.01`）。
其余仍带 `repeatWeight` 的增益（涌泉烙印 C52 等）不受影响。

界面侧（第 2 条需求）：**虚空铭文的三选一会把「已经附魔过」的候选标出来** ——
按钮第二行写「· 已附魔（不占位）」并换成紫色样式（`pick-done`），说明文字追加
「标着「已附魔」的已经生效过了 —— 再选一次不会多出收益，优先挑没标的」。只是**标注**，不禁用。

实现与守卫：

- `Tower.buffWeightOf` 里读 `mods.weightDivBy`（`'enchanted'` 看 `run.slotFreeIds.length`、
  `'owned'` 看 `obtainedCountOf`，都按 `初始 ÷ max(1, n)` 结算）；
  新增 `Tower.limitedRarityExtraOf` / `Tower.limitedGrantWeightOf` 两个只读接口供测试核对倍率；
- `tower-data` 的 `ENDLESS_ONLY_MODS` 收进 `freeSlotWeight` / `limitedRarityMul` 两个新键
  （挑战塔若误挂会加载期报错），`tools/test-buff-tags.cjs` 的白名单同步；
- 回归守卫 **需求93**（E01 的稀有度与折扣 + 两券合并仍 3.5 折 + C37 权重逐层减半 + C59 80×层数 +
  刷新 70 封顶而收益 50 封顶 + C58 全池逐个核对倍率与「史诗及以上份额下降」，
  并把 `需求15/75/11/12/54/9.6/9.8` 里过期的旧数值一并更新）；
- `test-mint-shop` 新增「虚空铭文三选一标注已附魔」的界面用例（渲染真 `openPickBuff`
  再核对按钮文案 / 样式 / 说明，并验证点下去仍然能选）。

## 优化：商店「出售增益 / 免费交换」列表的排序（2026-10）

两处「挑自己一条增益」的列表（试炼商店的**出售增益**、铸币商店的**免费交换**）改成：

回归守卫：`需求92`（最新在最上 / 叠层不改号 / **拿最新那条附魔**验证它从第 1 行掉到最后一行 /

## 修 Bug：三侠削弱跨层保留（2026-10）

**现象**：三侠（螳螂 / 仙鹤 / 熊猫）大招留下的削弱——「重伤」（生命上限 −8%）、「战吼」（随机属性 −8%）、
「压制」（随机锁一把武器 / 一个技能）——**换层之后还在**，与描述不符：数据注释写的是
「**打到本层结束**都一直在的削弱」，界面写的是「本层已被削弱（贯穿本层）」。

**根因**：`advanceLayer()` 只重置了 `layer / plan / idx / choices / restShopUsed`，**没清 `run.debuffs`**，
而 `adjustMe()` 每场都无条件读它 → 削弱跟着玩家一路叠到结算（每层三位大侠各留一条，越走越残）。

**修法**：

- `advanceLayer()` 里 `run.debuffs = []`（放在 `layerStartHeal` **之前**：新层的回血不该按被压低的上限算）；
- 削弱条目记下 `layer` 字段（存档校对 / 调试台观察用）；
- `normalizeRun` 做一次去重（同一来源只留一条），顺手清掉老档里堆下来的同源重复；
- `_debugSetEndlessLayer`（调试挪层）与 `advanceLayer` 同口径，也清；
- **E15 时间回廊重开的是同一层 → `restartLayer` 不清**（同层继续吃这套削弱，与「贯穿本层」一致）。

**回归守卫 `需求91`**：让第 1 场的三侠真的放大招落一条削弱 → 同层第二场仍在且 `adjustMe` 确实被压制
（上限 / 属性 / 锁武技三种都覆盖）→ 打完本层换到第 4 层后 `run.debuffs` 必须为空 →
把旧条目塞回去又会压制（证明清空就是那个开关）→ E15 同层重开时削弱**保留** →
外加「界面文案 = 本层」「`advanceLayer` 里确实有那行」「`restartLayer` 里确实没有」三条源码口径守卫。

## 狂怒终乘口径 + 涅槃每层计数修复 + 铸币商店「返回」不收摊（2026-10）

**① 狂怒（C20）：敏捷/速度的加成也是「终乘」**

三项现在统一按「乘在最终值上」结算，写法与面板也统一成 ×N：

| 项目 | 结算位置 | 面板/描述写法 |
|---|---|---|
| 最终伤害 | `sim.js` 的 `applyDamage` 最后一步（`lowHpFinalMul`） | 最终伤害 ×1.5 |
| 最终敏捷 | `sim.js` 的 `effAgility` 最后一步（`lowHpAgilityMul`） | 最终敏捷 ×1.2（终乘） |
| 最终速度 | `sim.js` 的 `effSpeed` 最后一步（`lowHpSpeedMul`） | 最终速度 ×1.2（终乘） |

`effAgility` / `effSpeed` 是引擎读取敏捷/速度的**唯一出口**（命中率、闪避率、出手频率、
野球拳与仙鹤的（力+速）伤害都读它），乘在这里 = 不会被任何别的乘区稀释；
`buffFlat`（越战越勇 / 后发制人这类回合成长）也算在这层乘法**里面**。

顺带修掉一个显示 bug：效果清单/面板的 C20 那一行读的是 `lowHpPowerMul`，
而 C20 早就改成 `lowHpFinalMul` 了 —— 于是面板一直显示「攻击 +0%」。现在三项都按 ×N 展示。
新增 `Sim.effStatsOf(fighter)` 供测试直接核对「终乘乘在哪一层」（满血 120 → 低血 144，而不是 +24）。

**② 涅槃（C14）「每层 N 次」在真实战斗里从来没记过账**

`reportBattle(mode, token, win, hp, maxHp, **result**)` 靠报告里的 `rounds` 数
`deathSave && revive` 的次数，而界面的 `onEnd` 只传了 5 个参数 —— **`result` 一直是 undefined**，
计数永远不涨，于是「每层 1 次」在真实战斗里退化成「每场 1 次」（用户报的现象）。
同一个根因还让隐藏成就「死而复生」（`run.deathSaves`）永远不触发。

修法：`js/tower-ui.js` 的 `onEnd` 把战斗结果 `r` 一起交给 `reportBattle`（就是模拟器那份带 `rounds` 的对象）。
回归守卫 `需求89` 走**真实 `Sim.simulate`**（玩家会被打死 → 真的触发涅槃），核对：
赛前次数 = 层数 − 本层已用、用掉几次记几次、打满后本层不再补、**换层才重置**、
`run.deathSaves` 同步增长，外加一条「界面必须把结果传进去」的源码断言。

**③ 铸币商店的「返回」不收摊；只有交易 / 「继续战斗」才收摊**

| 操作 | 结果 |
|---|---|
| 页脚「返回」 | **只是回上一页**，店不收摊（首页按钮仍写「进入铸币商店」，想好了再进来） |
| 页脚「继续战斗」（原「送客（离开）」） | 收摊，回首页继续打 |
| 完成一次购买 / 一次免费交换 | 收摊（沿袭原口径） |
| 免费刷新 / 讨价还价对折 | 不影响收摊判定 |

**④ 调试台新增无尽塔专属按钮：「立即生成一个铸币商店」**

走正式开店路径（掷货架 / 兑现讨价还价 / 发 C59 进门币 / 剥掉旧店），只是**不记「本组已刷过」**，
所以手开一家不会把这一组自然刷出的机会吃掉。接口是 `Tower._debugSpawnMintShop()`（无对局时返回明确提示）。

**⑤ 测试基建再加一个开关：`Tower._debugSetNoMintShop(true)`**

铸币商店的**自动**刷出也会在层中突然弹店、打断「一场接一场」的假设（`需求44` 幻影回响偶发红就是它）。
新开关只掐 `reportBattle` 里的那一次自动掷骰 —— `mintRollOf`（读概率的测试/探针）与
`_debugSpawnMintShop`（手开一家）都不受影响。`test-fixes-round` / `test-tower-plan` 的 setup 打开它，
要测铸币商店的用例自己 `_debugSetNoMintShop(false)`。

## 铸币商店概率随深度提升 + 讨价还价改成「每页都触发」（2026-10）

**① 铸币商店的刷出概率：5% 起步，每 5 层 +0.5%，10% 封顶**

```js
mintChance(layer) = min(0.10, 0.05 + (⌈layer/5⌉ − 1) × 0.005)     // TowerData.mintChance
```

| 层数 | 1~5 | 6~10 | 11~15 | 16~20 | 21~25 | 26~30 | 31~35 | 36~40 | 41~45 | 46~50 | 51+ |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 概率 | 5% | 5.5% | 6% | 6.5% | 7% | 7.5% | 8% | 8.5% | 9% | 9.5% | **10%（封顶）** |

「每 5 层」用的是无尽塔既有的**段**（`endlessSegment = ⌈n/5⌉`），所以第 2 段（6~10 层）就是 5.5%，
第 11 段（51 层起）触及 10%。层区间与「同一组连续三层只出一次」的规则都不变；
`mintChance` 是纯函数（归一到千分位，避免 `0.05 + 2×0.005` 这种浮点尾巴），界面与测试共用。

**② 讨价还价（E14）：商店**每一页刷新**都重新触发**

原来只在**进店那一刻**给那一页打对折，刷新货架就没了。现在进店时把「攒下的份数」兑现成
**这家店每页几件对折**（记在 `shop.halfPerPage`），之后**每次刷新出的新一页都按同一个数重打一遍**
（`rerollShop` / `rerollMintShop` 都走这条口径）：

- 试炼商店：免费刷新与之后的付费刷新，新一页照样有 N 件对折；
- **铸币商店**：免费刷新的新一页同样触发（与试炼商店一致）；
- 刷新**不再额外消耗**玩家攒下的份数（份数只在进店那一刻兑现一次；一页装不下的余量照旧留到下一家店）；
- 两个商店页的刷新卡片都会写清「讨价还价：新一页同样有 N 件对折」，免得玩家以为只有第一页。

回归守卫：`需求87`（概率曲线 + 第 7 层 / 第 57 层各 4000 次采样）、`需求88`（试炼商店免费/付费刷新、
铸币商店免费刷新都重新触发，且不扣份数）、以及 `test-mint-shop` 里对应的两条（该文件在 CI 里跑）。

## 新增：传奇限次 1「时间回廊」（E15，2026-10）

- **规则**（`js/tower.js`）：`hasActiveLayerRestart(run)` 在 `consumeLimited` **之前**取一次

## 修 Bug：E01「立即进货」开的店进得去出不来（2026-10）

现象（用户报）：用「下一场战斗结束后立即开启试炼商店」（E01 立即进货）开的店，
进店之后没法正常离开、回去继续挑战 —— 首页按钮一直写「进入试炼商店」，点了又回同一家店。

根因在**界面**那条「离开」分支（`tower-ui.js` 的 `on(p, 'leave')`）：它按 9.8 轮的判据分了两支，
但「休整 / 战后立即进货 / 立即开店」那一支只调了 `openEndless()`、**没有真的关店**：

```js
if (revisit || shop.rest || shop.postBattle || !shop.boundary) { openEndless(); return; }   // ← 没关店
```

于是 `run.phase` 还停在 `'shop'`（`run.shop` 也还在）：

- 首页按钮按 `phase === 'shop'` 渲染 → 继续写「进入试炼商店」→ 点进去还是那家店（看着就是出不去）；
- 想直接继续战斗也不行 —— `nextBattle()` 第一道闸就是 `if (run.phase) return { ok:false, msg:'请先完成商店与结算。' }`。

实测复现（E01，第 7 层第 1 场打完）：

```
打完：phase=shop  shop=open postBattle=true   首页按钮「进入试炼商店」
旧离开分支 → phase=shop        首页按钮仍是「进入试炼商店」
此时 nextBattle → 被挡下：请先完成商店与结算。      ← 用户报的现象
```

修法两处：

| 位置 | 改动 |
|---|---|
| `tower-ui.js` 商店页「离开」 | 那一支先调 `Tower.closeShop()` 再回首页（`closeShop` 会按「这家店怎么开的」把 phase 归位） |
| `tower.js` `closeShop()` | **顺便把 `run.shop` 也清空**：只归位 phase 的话 `shopState()` 仍然拿得到一家店，界面还会以为「有店等着进」 |

修好之后同一条路径：`closeShop()` → `phase=null`、`shop=null` → 首页按钮变回「继续战斗」→
下一场直接开得起来。回归守卫：`tools/test-mint-shop.cjs` 第 9 节（**真的用界面桩点一遍**：
E01 进店 → 点「继续挑战」→ 断言 phase/shop 归位、首页按钮变回「继续战斗」、下一场能开），
外加需求9.8 的两条新断言（关店后 `run.shop` 必须为空、界面「离开」分支必须调 `Tower.closeShop()`）。

**② 枯泉·涸井：生命乘数 1.06 → 0.96**

- `skillWeight`（玩家 / 无固定循环的敌人）：权重本身就是那条曲线（`repeatRateOf(12, 已用次数)`）；
- `yakyuGated(att)`：**固定循环型敌人**（元素术鼠那种「技能 → 普攻 → 技能」的循环）不看权重，
  所以每次要放它时按曲线掷一次，没抽中就把 12 排除出可用技能 —— 有别的技能就让位，没有就改普攻。

## 新机制：无尽塔「铸币商店」（2026-10）

5 层之后的 **x2 / x3 / x4 与 x7 / x8 / x9 层**，每场战斗打完有 **`mintChance(layer)`** 的概率刷出一家
**铸币商店**（5% 起步、每 5 层 +0.5%、10% 封顶 —— 见上一节）；
**同一组连续三层**（x2~x4 或 x7~x9）里最多刷出一次（组号记在 `run.mintGroup`）。

| 项目 | 规则 |
|---|---|
| 货架 | **5 件**；稀有度 ≈「试炼商店花 **40 试炼币**刷新」的排布，普通档权重再压一档（实测 ≈ 普通 20% / 稀有 33% / 史诗 32% / 传奇 15%） |
| 上架倾向 | 非传奇档**大概率（80%）运营类**；**传奇档不受此限**（可以是任何传奇件） |
| 售价 | 按稀有度**固定**、不吃 E01/E04 任何折扣：普通 **0** / 稀有 **1** / 史诗 **2** / 传奇 **3 铸币** |
| 交易 | 花铸币买走 1 件，**或**免费拿自己已有的 1 件（永久 / 限次）去换 1 件；**做成其一店立刻收摊**，也可以直接送客 |
| 免费刷新 | **一次**；刷新之后**不能再交换**（仍然可以买） |
| 免费交换 | 大概率（80%）→ **同稀有度运营类**（普通件另有 50% 升成稀有件）；小概率 → 同稀有度非运营；某一支抽空时逐级退回，绝不空手 |

「**运营类**」是新登记的标签 `ops`（数据里显式写在 `tags` 上，共 18 条）：
试炼币（E02/E03/E05/E06）、商店（E01/E04/E12）、铸币（E09/E10）、出售（C24/C25）、
商店消费（C36/C58/C59）、槽位扩容（C30/C31/C37）、试炼币烙印（C53）。

实现要点：

- **数据侧**（`js/tower-data.js`）：`MINT_SHOP`（概率 / 层区间 / 件数 / 价格 / 两个「大概率」/
  普通档升稀有档）+ `mintLayerOk` / `mintGroupOf` / `mintPrice` / `mintWeights` / `rollMintRarity`；
  `mintPool` = 全部无尽增益**除掉铸币类**（E09/E10 —— 用铸币买铸币会套利：花 2 枚买到 3 枚）。
  两条加载期守门：`ops` 只能挂在无尽塔增益上、四档稀有度都要有可上架的商品。
- **规则侧**（`js/tower.js` 【T17b】）：`reportBattle` 打完一场后判定（**放在幻影回响之后**，
  同一场不会摇两次；这一场已经由 E01 开了试炼商店就顺延，组号也不记 → 本组后面还能刷）；
  **整层最后一场也照算**（在 `layerClear` 之后挂店）。`buyMintSlot` / `swapMintBuff` /

## 修 Bug：涌泉烙印（C52）根本没生效（师父驾到等治疗不加成）（2026-10）

现象（用户报）：涌泉烙印没生效 —— 至少对「师父驾到」（技能 13）没生效。


全都吃不到加成。修法：`makeCombatant` 读 `f.healMul`（≤0 也照读，枯泉的封疗就是把它置 0）。

**根因 2（联动）**：C49「终焉烙印」和 C52「涌泉烙印」**共用一份层数** `run.fragileMulBase`

自己的计数，治疗这条当时漏了。修法：

- C52 去掉 `fragileFinalMul` 标记，改用自己的一套：`run.fragileHealBase` / `run.fragileHealBurned`
  （与 C53 同一套形状），获得 / 损毁 / 卖出三条路径都各自记账；
- `normalizeRun` 做一次性迁移：老存档里把「持有的 C52 层数」从 `fragileMulBase` 里摘出来还给
  `fragileHealBase`（否则老存档的治疗加成为 0、而 C49 的倍率被 C52 层数虚高）。

**联动范围**（都统一乘 `healBonusMul(run) = 1 + fragileHealBonus(run)`）：
C11 胜利回血、C13 精英回血、C01 获得时回血、开战回血（C10/C16/C17、N08/G02/T07）。
层间结算回血（`ENDLESS_LAYER_HEAL_PCT`）与自动回血（`AUTO_HEAL_PCT`）是**规则回血**、不是增益给的，不乘。

验证：师父驾到（师父 4 级）在 healMul 1 / 1.1 / 1.2 下分别回 **16 / 18 / 19**，枯泉封疗时 **0**；
只有 C49 时不再有治疗加成（`healMul` 仍是 1），只有 C52 时 `fragileMulBase` 仍是 0（不再白给 ×1.25），
两条各 1 层时治疗 = ×1.1、终乘 = ×1.25（都不是被对方带偏的 1.2 / 1.5）。

回归守卫：「需求9.9」（test-fixes-round 90 → 91 项）锁住上面全部结论 + 老存档迁移；

（顺带把「需求56」里「C52 应当挂终乘标记」的旧断言改成新语义。）

## 修 Bug：E01「立即进货」关掉之后仍然每场开店（2026-10）

`E01 立即进货` 的效果原来是**拿到那一刻写死**在 `run.postBattleShop` / `run.shopDiscount`
上的，而限次增益的「开关」（`limited[].on`）只在 `eachBuff` 聚合时才被尊重 ——
于是玩家把 E01 关掉之后，缓存还在，**每场战斗结束照旧进商店**。

改成**按「现在开着的 E01」现算**：

- 新增 `activeShopCredit(run)`：只看 `on !== false` 且 `uses > 0` 的立即进货条目；
- 战后判定在**扣限次之前**取这份折扣（E01 的限次就消耗在这一场，扣完条目会被移除）；
- `makeShop(run, e01Pct)` 把「即时折扣券（steam大促 E04 −30%）」与「E01 当前这一份
  （−50%）」在**开店那一刻**合并（两者同时生效 → −65% = 3.5 折，谁先拿都一样）；
- `run.postBattleShop` 缓存字段彻底删除（旧档在 `normalizeRun` 里清掉），
  E01 关闭时不再开店、也不消耗次数（与「关掉不扣次数」的口径一致）。

`tools/test-fixes-round.cjs` 的「需求15」加了回归：关掉后连续几场都不开店、重开恢复生效且只开一次、
E01+E04 合并仍是 3.5 折。

## 本轮改动（2026-10）

**① 随机挑战经验下调 + 等级差增幅收窄**
同级基准 `20 + 等级×0.65` → **`16 + 等级×0.55`**（20 级：33 → 27，−18%）；
等级差线性 `+14%/级 / 压实 0.88` → **`+9%/级 / 压实 0.78`**，
同样越 3 级：倍率 1.36 → **1.22**、经验 45 → 33（−27%）。
竞技场保持不动（4 人两轮、要赢才拿满，单位体力看期望仍与随机挑战同档）。

**② 道具界面按钮顺序**：背包一级界面的「卖出」挪到「使用/合成」**左边**
（主操作仍是最醒目的金色按钮）。

**③ 增益标签系统（严格池子管理）**：每条增益显式写 `tags: [...]`，
池子只认标签 —— 挑战塔只出 `tower`、无尽塔只出 `endless`（增益集锦也不再出现挑战塔专属）、
战斗掉落只出 `battle`、商店只卖 `shop`；可叠层 / 每局限次获得 / 同名唯一 / 隐藏
也都有独立标签。
**旧的布尔字段（towerOnly / endlessOnly / battleOnly / shopBanned / stackable /
repeatable / unique / nextBattle / hidden）已全部删除**，数据里再写就是加载期报错 ——
