## 二、方法论：怎么比、比什么

### 2.1 证据规则

- 原版一律以 `references/ssfight/ssfight/ssfight/resource/动作/MainMovie.as` 为准。
  `references/` 里另有两份同内容副本（`unpacked/03-反编译源码/` 下），行号可能差几行，**不引用**。
- 原版数据表以 `references/orig/GameDict.js` 与 `MainMovie.as` 内嵌数组为准。
- 新版以仓库根目录 `js/` 下源码为准。
- 每条结论都要给**两侧行号**，便于复核。

### 2.2 通用流程（每块五步）

1. **定位两侧真源** —— 原版找 `MainMovie.as` 的函数/内嵌数组 + `GameDict.js` 字典；新版找 `js/` 对应文件。
2. **提取可比字段** —— 把两侧数据规范成同一张表（字段名对齐）。
3. **找官方口径** —— 原版客户端嵌了大量**官方帮助文本**（如融合帮助 `L19521`），
   这是最权威的设计意图，优先级**高于**代码推断。
4. **逐项判定** —— 一致 / 有差异 / 缺失 / 新增。
5. **产出决策表** —— 差异项列成表，标注影响面（数值 / 玩法 / 手感）与改动成本，等用户拍板。

### 2.3 本仓已知的**结构性**差异

这几条影响所有块，先说清楚，后续各章不再重复：

| 差异 | 原版 | 新版 | 后果 |
|---|---|---|---|
| **战斗计算位置** | 服务端权威，客户端只有 `parseFightLog()` 解析 + `attack()` 播动画，**零伤害公式** | `js/sim.js` 自己算 | 战斗公式无法「对照原版」，只能重新设计或用抓包日志反推 |
| **数据表粒度** | 装备属性点独立成表 `equipsArray`（288 条） | **没有该表**，主属性来自 `gearMap.abilities` 的 4 位数组 | 原版每件装备有独立数值，新版同部位**共用同一个值** |
| **词条维度** | 星级(1-3) × 升级计数(1-12) **两个维度** | 只有星级；`attachmentMap` 缺第 3 列 | 原版词条可长期成长，新版 3 星封顶 |
| **品质级数** | 白/绿/蓝/紫/橙/**黑**（6 级） | 白/绿/蓝/紫/橙（5 级） | 原版顶级内容（黑装）新版没有 |
| **服务端接口** | 60+ 个 `.do` 接口，逻辑在后端 | 无后端，纯前端 | 原版"规则"多数要从客户端**调用点**反推 |

### 2.4 原版数据的三类载体

找原版数据时按这个顺序找，命中率最高：

1. **`GameDict.js` 字典** —— `new Map("字段1,字段2,…")` + 逐条 `.put(id, [...])`。
   新版由 `tools/gen-vendor-data.cjs` 抽成 `js/gamedict.js`，**字段名与条目一一对应**，最好比。
2. **`MainMovie.as` 内嵌大数组** —— `var xxxArray = [[...],[...]];` 单行超长。
   常见：`equipsArray`(L19142) / `attachmentArray`(L19143) / `propsArray`(L19137) /
   `giftsArray` / `upgradesArray` / `petsInfo`。**新版 gamedict 里没有的，多半就在这类数组里。**
3. **`MainMovie.as` 里嵌的 `helpWords`** —— 官方文案，设计意图最权威。

> 实用技巧：`attachmentArray` 之类单行超长数组，用 `json.loads()` 直接解析整段最省事
> （见 `out/extract_ch1.py` 的做法：正则取出 `= [ ... ];` 再 json 解析）。

## 三、推进顺序（建议）

按「**改动收益 / 成本比**」排序：

| 顺序 | 块 | 理由 |
|---|---|---|
| 1 | **第 1 章 装备词条与融合** | 已完成 ✅ |
| 2 | **第 13 章 数值平衡总表** | 先把两侧全量数值拉平对齐，后续所有块都依赖它 |
| 3 | **第 4/5 章 武器与技能** | 已有 `docs/真化武器与技能数值.md` 可复用 |
| 4 | **第 6 章 关卡与 NPC** | 直接影响战斗难度 |
| 5 | **第 3 章 属性/被动/小宇宙** | 与第 1 章词条（effect 类）强耦合 |
| 6 | **第 2 章 战斗伤害公式** | 原版无客户端公式，需用抓包战斗日志反推，成本最高，**建议放最后** |
