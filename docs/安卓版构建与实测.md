# 安卓版（APK）构建与实测记录

> 目标：给「松鼠大战怀旧复刻版」出一个**能在安卓手机上安装运行**的安装包。
> 现状：**已跑通并在模拟器上实测通过**（能装、能开、画面正常、可触摸、存档可写可读）。
> 本文记录做法、踩过的坑、以及还没做的事。

## 一、结论速览

| 问题 | 结论 |
|---|---|
| 原来的 Windows exe 能装安卓吗？ | **不能。** 它是 PE32+ / x86-64 / Windows GUI 子系统，依赖 `kernel32`/`user32`/`WebView2`，安卓上连加载器都不认 PE |
| 游戏本身能在安卓跑吗？ | **能。** 游戏是纯 HTML/JS，实测在安卓 WebView（Android 15 / x86_64 模拟器）里完整运行 |
| 用什么方案做的？ | **Tauri 2 的 Android 支持**（同一个 `src-tauri` 同时产出 Windows exe 和 Android APK） |
| 存档在哪？ | 应用私有目录：`/data/user/0/com.ssdz.classic/save/progress.json` |
| 和网页版/桌面版是同一份存档吗？ | 是同一个逻辑与格式，但**文件位置不同**（手机上是应用私有目录，电脑上是 `save/progress.json`）；跨设备要用游戏里的「系统 → 导出/导入存档」或双机同步 |
| 安卓上会失去什么？ | `启动游戏.cmd` 那套启动器、`scripts/sync/` 的双机同步（它们依赖 Node/Python 进程），以及"存档文件直接可见可拷" |

## 二、一键构建

```powershell
# 模拟器（x86_64）
pwsh -File tools\build-apk.ps1 -Abi x86_64

# 真机（绝大多数手机是 arm64）：Rust 侧用 release 编译，体积小很多
pwsh -File tools\build-apk.ps1 -Abi arm64-v8a -Release

# 产物会自动复制到 src-tauri\dist\，名字带架构/用途/日期：
#   src-tauri\dist\squirrel-fight-arm64-v8a-0.4.5.apk   ← 真机装这个（146.1 MB；脚本默认名是
#                                                          ssdz-classic-<abi>-<profile>-<日期>.apk，可随意改名）
#   src-tauri\dist\ssdz-classic-x86_64-debug-20261008.apk          ← 模拟器用
# 原始产物仍在 gen\android\app\build\outputs\apk\<flavor>\debug\ 下。
```

> 注意两点（都是踩过的）：
> - `tauri android build` **默认就是 release**，只有 `--debug` 这个反向开关——传 `--release` 会报
>   `unexpected argument '--release'`。
> - Gradle 侧**始终用 Debug 变体**：`assembleRelease` 出来的是**未签名** APK，手机上装不上；
>   Debug 变体自带 debug 签名，可以直接装。Rust 侧该 release 还是 release（决定 `.so` 体积：
>   debug 185 MB vs release 68.5 MB）。

脚本做的事（顺序不能换，换了就会白屏或链接失败）：

1. 同步源码到**纯 ASCII 路径**的构建副本 `E:\ssdz-android-build`
2. `node tools/build-tauri-web.cjs` 暂存前端到 `src-tauri/web`
3. 用 `tauri android build` 编译 Rust（借它准备 NDK 交叉编译环境）
4. 手工把 `libssdz_classic_lib.so` 放进 `gen/android/app/src/main/jniLibs/<abi>/`，
   并把 `web/` 拷进 `gen/android/app/src/main/assets/`
5. 从仓库里的 `gen/android` 同步**图标（res/）与 AndroidManifest.xml** 到构建副本
   （只同步这两样，绝不动 `buildSrc`——那里有 node 路径的补丁）
6. `gradlew assemble<Flavor>Debug` 打包（Debug 变体自带签名，能直接装）
7. 产物复制到 `src-tauri\dist\`；有设备连着就顺手 `adb install -r` 并启动

## 三、代码上改了什么

### 1. `src-tauri` 拆成 bin + lib（同一个 crate 两种产物）

- `src-tauri/src/lib.rs`：**全部逻辑**。按 `cfg(mobile)` / `cfg(not(mobile))` 分支：
  - 桌面：保留原来的「自己找游戏目录 + 内置迷你 HTTP 服务器 + `/__save`」；
  - 移动：前端嵌在安装包里（资源协议伺候），**不找外部目录、不起服务器**，
    存档写 `app_data_dir()`。
  - 入口 `pub fn run()` 带 `#[cfg_attr(mobile, tauri::mobile_entry_point)]`
    （注意：`tauri::mobile_entry_point` 是**属性宏**，不能写成内部属性 `#![cfg_attr(...)]`，
     否则报 `error[E0658]: inner macro attributes are unstable`）。
- `src-tauri/src/main.rs`：桌面可执行入口，只有 8 行，转调 `ssdz_classic_lib::run()`。
- `Cargo.toml`：`[lib] name = "ssdz_classic_lib"` + `crate-type = ["lib","cdylib","staticlib"]`。

**关于可执行文件名（2026-10 改名）**：桌面 exe 从 `ssdz-classic.exe` 改成了 **`squirrel_fight.exe`**。
改法是给 `[[bin]]` 单独取名，`[package] name` 仍是 `ssdz-classic`：

```toml
[[bin]]
name = "squirrel_fight"     # 决定编出来的 exe 文件名
path = "src/main.rs"
```

⚠️ 因为 Tauri 打包器默认**按包名**去找要打包的二进制，改名后必须在 `tauri.conf.json` 里
同时补一个 `"mainBinaryName": "squirrel_fight"`（Tauri 2 的正式字段），否则打安装包会找不到
`ssdz-classic.exe` 而失败。

**安卓侧完全不受影响**：Android 构建走的是 `--lib`（加载 `libssdz_classic_lib.so`），
和 `[[bin]]` 的名字无关——所以 `[lib] name` 千万不要跟着改，否则要同步改
`gen/android` 里的 jniLibs 目录与 gradle 配置。

### 2. `src-tauri/tauri.android.conf.json`（只在 Android 构建时自动合并）

```json
{
  "build": { "frontendDist": "web" },
  "app": {
    "windows": [
      { "label": "main", "url": "index.html", "title": "松鼠大战 · 怀旧复刻版", "resizable": true }
    ]
  },
  "bundle": { "android": { "minSdkVersion": 24 } }
}
```

**`app.windows` 这一段是必须的**：Tauri 的 `setup()` 只按配置里的 `windows` 数组建窗口
（`tauri/src/app.rs` 里 `for window_config in app.config().app.windows.iter().filter(|w| w.create)`）。
桌面版是在 Rust 代码里 `WebviewWindowBuilder` 建窗口，所以 `tauri.conf.json` 里一直是
`"windows": []`；移动端不能这么干，于是空数组 = **一个窗口都不建 = 一片白**。

### 3. `js/tauri-bridge.js`

- **轮询等 `window.__TAURI__`**：移动端它是异步注入的，页面解析阶段经常还没有。
  原实现只查一次就 `return`，导致手机上永远走不到 Tauri 存档通道。
- 成功后设置 `window.__SSDZ_TAURI_APP__ = true`，供界面判断文案。
- 诊断默认关闭，加 `?ssdzdbg=1` 打开（信息写进 `document.title` 与 console；
  Android 上 `adb logcat | findstr ssdz-bridge` 能看到）。

### 4. `js/state.js` / `js/main.js`（体验）

首次运行时"通道正常但还没有存档文件"以前会被当成故障弹**红色报错横幅**（文案还写死了
「请用启动游戏.command 重新启动」，在手机上很误导）。现在：

- `fileState.transportReady` 区分「通道坏了」和「只是还没有存档文件」；
- 后者显示一条绿色的说明条（不吓人），并且**第一笔存档写成功后自动消失**。

### 5. 安卓图标与横屏

- **图标**：`cd src-tauri && npx tauri icon app-icon.png` —— 它会**直接写进**
  `gen/android/app/src/main/res/mipmap-*/`（各密度 `ic_launcher.png` / `_round` / `_foreground`），
  替换掉 `tauri android init` 生成的默认安卓机器人图标。
- **横屏**：`gen/android/app/src/main/AndroidManifest.xml` 的 activity 上加
  `android:screenOrientation="sensorLandscape"`（可左右翻转的横屏）。
  游戏是 1216×760 的横向比例，竖屏下只占中间一条、上下大片留白；锁横屏后铺满 2340×1080，
  HUD 与底部按钮一行排开（对比 `out/android-emulator-9.png` 竖屏 vs `out/android-landscape.png` 横屏）。
- **Tauri 的安卓配置里没有朝向选项**（`gen/schemas/android-schema.json` 里搜不到 `orientation`），
  所以只能写在清单里，属于「生成工程里的补丁」之一，见下一节。

## 四、生成工程里的三处补丁（重新 `tauri android init` 后要重打）

`src-tauri/gen/android/` 是 `tauri android init` 生成的 Android 工程，**不进仓库**（已加进 `.gitignore`，
因为可再生产）。但我对里面三个文件做了必要修改，重新生成后要照下面再补一次。
（图标与清单这两项，`tools\build-apk.ps1` 每次构建都会从仓库里的 `gen/android` 同步到构建副本，
所以只要仓库那份是对的就行；`BuildTask.kt` 的补丁在构建副本里，重新 init 后要手工再打。）

### 1. `gen/android/buildSrc/src/main/java/<包路径>/kotlin/BuildTask.kt`

这个文件里 Tauri 的模板把 node 路径**硬编码**了，而且多一个分号：

```kotlin
val executable = """C:\Program Files\nodejs\node""";   // ← 路径带空格，project.exec 起不来
try { runTauriCli(executable) } catch (e: Exception) { /* 试 .exe/.cmd/.bat */ }
```

改成按顺序试（`NODE_EXE` → PATH 里的 `node` → 常见安装位置），并且**在 `.so` 已存在时直接跳过**：

```kotlin
@TaskAction
fun assemble() {
    // .so 已经手工放进 jniLibs/<abi>/ 时直接返回，不调会 panic 的 CLI 入口
    val abiDir = when (target) {
        "aarch64" -> "arm64-v8a"; "armv7" -> "armeabi-v7a"
        "i686" -> "x86";          "x86_64" -> "x86_64"; else -> null
    }
    if (abiDir != null) {
        val so = File(project.projectDir, "src/main/jniLibs/$abiDir/libssdz_classic_lib.so")
        if (so.exists()) { logger.lifecycle("rust build 跳过：已存在 ${so.absolutePath}"); return }
    }
    val candidates = mutableListOf<String>()
    System.getenv("NODE_EXE")?.let { if (it.isNotBlank()) candidates.add(it) }
    candidates.add("node")
    if (Os.isFamily(Os.FAMILY_WINDOWS)) {
        candidates.add("node.exe"); candidates.add("node.cmd")
        System.getenv("ProgramFiles")?.let { candidates.add(File(it, "nodejs/node.exe").absolutePath) }
    }
    var last: Exception? = null
    for (c in candidates) { try { runTauriCli(c); return } catch (e: Exception) { last = e } }
    throw (last ?: GradleException("找不到 node：请加进 PATH 或设置 NODE_EXE"))
}
```

### 2. `~/.gradle/init.gradle`（机器级配置，不在仓库里）

本机的 Maven/Google 仓库要走代理，而 Java 对系统代理不友好（`Remote host terminated the handshake`）。
所以走**阿里云镜像**：

```groovy
def MIRRORS = ['https://maven.aliyun.com/repository/public',
               'https://maven.aliyun.com/repository/google',
               'https://maven.aliyun.com/repository/gradle-plugin',
               'https://maven.aliyun.com/repository/central']
def applyMirrors = { repos -> MIRRORS.each { u -> repos.maven { url = u; allowInsecureProtocol = true } } }
settingsEvaluated { s ->
  applyMirrors(s.pluginManagement.repositories)
  applyMirrors(s.dependencyResolutionManagement.repositories)
}
allprojects { p -> p.buildscript.repositories { r -> applyMirrors(r) }; p.repositories { r -> applyMirrors(r) } }
```

配合：构建前把系统代理临时关掉（`HKCU:\...\Internet Settings` 的 `ProxyEnable=0`），
构建完恢复；Gradle 发行版本体可以用 `curl --ssl-no-revoke` 手工下到
`~/.gradle/wrapper/dists/gradle-8.14.3-bin/<hash>/gradle-8.14.3-bin.zip`。

### 3. `gen/android/app/src/main/AndroidManifest.xml`（锁横屏）

在 activity 上补一行（Tauri 没有对应的配置项，只能写在清单里）：

```xml
<activity
    android:configChanges="orientation|keyboardHidden|keyboard|screenSize|locale|smallestScreenSize|screenLayout|uiMode"
    android:launchMode="singleTask"
    android:label="@string/main_activity_title"
    android:name=".MainActivity"
    android:screenOrientation="sensorLandscape"   <!-- ← 加这一行 -->
    android:exported="true">
```

验证方式：`apkanalyzer manifest print <apk> | findstr screenOrientation` 会显示
`android:screenOrientation="6"`（6 = `sensorLandscape`）。

## 五、踩过的坑（按遇到顺序，都是真金白银）
| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | `linker cc not found` | 裸 `cargo build --target *-linux-android` 没有 NDK 交叉编译环境 | 用 `tauri android build` 触发编译（它会准备 CC/AR/linker） |
| 2 | `ld.lld: error: cannot open E:\\\xcb\xc9\xca\xf3...` | 项目路径 `E:\松鼠大战怀旧版` 含中文，NDK 的 `*-clang.cmd` 包装器在 Windows 上按 GBK 传参 | 复制一份到**纯 ASCII 路径**构建（`E:\ssdz-android-build`）。用目录联接不行——Cargo 会把路径规范化回真实中文路径 |
| 3 | Gradle wrapper `PKIX path building failed` | 本机系统代理（127.0.0.1:7897）对 Java 不友好 + 上次下载只留了 `.part` | 手工把 `gradle-8.14.3-bin.zip` 放进 `~/.gradle/wrapper/dists/...`；`curl` 下载要加 `--ssl-no-revoke` |
| 4 | 依赖解析 `Remote host terminated the handshake` | 同上，Maven/Google 仓库走代理不稳 | 写 `~/.gradle/init.gradle` 指向**阿里云镜像**（public/google/gradle-plugin/central），构建时临时关掉系统代理 |
| 5 | `Creation symbolic link is not allowed` | Tauri CLI 要把 `.so` **符号链接**进 jniLibs；本机没开开发者模式、没有 `SeCreateSymbolicLinkPrivilege` | 手工 `Copy-Item` 复制 `.so`（这正是脚本第 4 步） |
| 6 | `Process 'command 'C:\Program Files\nodejs\node.bat''` 启动失败 | Tauri 生成的 `BuildTask.kt` 把 node 路径**硬编码**成带空格的绝对路径（还多一个分号），`project.exec` 处理不了 | 改成按顺序试 `NODE_EXE` → `node` → `node.exe` → 常见安装位置 |
| 7 | `rustBuildArm64Debug` 报 `invalid value 'arm64'` | Gradle 的 `RustPlugin.kt` 把 `arm64` 当 target 传给 Tauri CLI，而 CLI 只认 `aarch64` | 别让 Gradle 调那个入口（见 #8） |
| 8 | `failed to read missing addr file ...-server-addr` panic | `tauri android android-studio-script` 这个入口是给 Android Studio 用的，纯 Gradle 环境下会 panic | 在 `BuildTask.kt` 里加判断：**jniLibs 里已经有 `.so` 就直接跳过**该任务 |
| 9 | APK 装上了、能开、**一片白** | `app.windows` 为空 → 移动端没有任何窗口；且前端资源没被嵌进去 | 配置里补 `windows`（见上）；先暂存 `web/` **再**编译 Rust（Tauri 在编译期嵌资源） |
| 10 | 界面出来了，但存档退回 localStorage | `window.__TAURI__` 在页面解析阶段还没注入，桥只查一次就放弃了 | 轮询等待（见上） |
| 11 | 首次运行弹红色"存档故障"横幅 | 通道是好的，只是还没有存档文件 | `transportReady` 区分两种情况（见上） |

## 七、还没做的事（下一步）

1. **真机还没装过**（唯一挡在"完成"前面的验证）：arm64 release 包已产出
   （`src-tauri\dist\squirrel-fight-arm64-v8a-0.4.5.apk`，146.1 MB），
   并且**在模拟器上用 arm64 转译实测跑通**（启动 + 读档 + 横屏都正常），但还没在真实手机上装过。
   装法：把 APK 传到手机（数据线/微信文件/网盘），点开安装，首次要允许「未知来源」。
2. **触摸可用性还没在战斗里验证**：菜单/背包这类点按没问题（代码里都是 `click`，触摸会自动合成），
   但战斗画布是固定 1170×690、`touchstart/touchmove/pointerdown` 事件数为 0，
   手机上摆干员、选技能好不好点，必须实机打一局才知道。**这是整个移植最大的未知数。**
3. **签名**：现在是 debug 签名（安装时系统会提示"来源不明"）。要给别人的手机长期用、
   或者上应用商店，需要自己的 release keystore（`keytool` 生成 + `signingConfigs` 接进
   `app/build.gradle.kts`）。这一步需要你自己定口令，所以没替你做。
4. **返回键**：`TauriActivity.handleBackNavigation = false`，安卓返回键目前直接退出应用；
   要不要改成"返回上级界面"取决于触摸体验怎么定（`handleBackNavigation` 只能改 Rust 侧的
   `TauriActivity` 子类或生成工程里的 `MainActivity.kt`）。
5. **磁盘占用**：构建副本 `E:\ssdz-android-build` 约 11 GB（其中 `src-tauri\target` 10 GB 是 Rust
   编译产物）。删掉能省 10 GB，代价是下次构建要重编 1~3 分钟（crate 本地有缓存、不用重下）。
   不再改安卓相关代码的话可以直接删整个目录。
