# 松鼠大战 · 怀旧单机复刻版

以 UC 乐园《松鼠大战》的经典界面截图为主要视觉参考，结合本地 Android 客户端中的素材、动画与数据，重建可离线游玩的怀旧版本。当前重点是经典首页、资料、武器技能与关卡界面的布局，以及养成、挑战和战斗回放流程。

## 启动

项目为静态网页，游玩不需要安装前端依赖或构建。建议通过本地服务器启动：

```powershell
node tools/serve.js 8080
```

使用 Chrome 或 Edge 打开 [http://127.0.0.1:8080/](http://127.0.0.1:8080/)。服务器仅监听本机。直接打开 `index.html` 可能受浏览器的本地文件限制，推荐固定使用同一地址和端口。

画面以 1170 × 690 为当前项目的逻辑尺寸，随窗口等比缩放；这不代表所有历史版本都使用相同分辨率。

## 当前内容

- 经典首页、角色资料、武器与技能分页、详情和升级。
- 随机挑战、对手预览、关卡 NPC、六档难度与挑战书消耗。
- 背包、商店、道具使用、装备穿脱与出售，以及选择三件材料、预览和确认的经典融合页面。
- 战斗记录、录像回放、好友与公告页面，系统中的声音、帮助、每日奖励、改名及存档导入导出。
- 村庄入口，以及师徒训练、竞技场、天梯赛和抽奖的本地流程。
- 松鼠与螳螂、仙鹤、熊猫等对手的战斗演出，以及多个战斗场景。

### 随机对手生成

`State.genAI(level, nameSuffix, opts)` 按下面几点生成对手：

- **等级范围更宽**：挑战页的 `genOpponents()` 用 `opts.levelJitter = 3`，三个对手分别在玩家等级 −1/0/+1 附近再浮动 ±3，实测 200 次采样覆盖 7 个不同等级（27~33）。
- **名字更多样**：`randomAIName()` 从固定昵称池或「前缀（24）× 核心词（24）」组合里取，少数再带称号（`的师傅 / 的师兄 / 的宿敌 / 二世`），300 次采样得到 212 个不同名字。
- **按等级随机穿装备**：`randomAIGears(foeLevel, refLevel)` 从 `gearSetMap` 里挑 `set.level ≤ 玩家等级` 的套装，每个部位最多一件，等级越高穿得越全（`0.35 + 等级/60`），并按等级概率附带随机附加属性。低等级玩家不会抽到超等级装备。
- 武器/技能数量与等级也随等级提高（数量 `2 + 等级/4`，等级上限 15）。

对手装备会经 `Engine.wearsFor(foe.gears)` 在战斗里真实绘制出来。

### 战斗随机性

`js/sim.js` 选武器时给「上一回合刚用过的那把」降权（`Math.random() < 0.25` 才允许复用，否则从其余武器里挑），而不是直接禁用——这样连续重复同一把武器的观感明显减少，又不会退化成机械式交替。实测连续重复率：2 把武器 50% → **12%**，4 把武器 25% → **5%**；只有 1 把武器时仍正常出手。

首页按参考图整理：顶部只保留名字、等级格子、体力、Exp 与金松果，等级、体力、Exp、金松果的数字使用原版位图数字 `num_28`（26×23 一格），由 `num()` / `renderNumbers()` 按设计尺寸画到 canvas 上，再交给 `#ui` 的 `--uiscale` 统一缩放，因此缩放时不会糊边；位图里的数字比参考图偏窄，统一按 1.25 倍横向拉伸（常量在 `js/debug.js` 的 `NUMBER_STRETCH`）。等级数字与其它数字同为 32px 高，并保持居中于格子。身份栏的昵称、等级格子与金松果都按参考图做成「金条 + 深棕内嵌槽 + 白色内描边」的两层背景：

- **昵称**：深棕内嵌槽 + 白字
- **等级格子**：深棕内嵌槽，位图数字居中
- **体力槽**：亮金色填充**从左侧起（0 在左）向右增长**，宽度 = 体力比；配色取自参考图填充段（`#fffdf0 → #ffe293 → #f2c76a → #d9a75e`），右边缘用整圆角 `border-radius:26px` 配内高光（`inset 0 2px #fffef4`）与外侧暗投影做出半圆形圆润收尾；未填充的右侧剩余部分是深棕，数字用白字加双层深色描边，在亮底与深底上都可读
- **金松果**：图标与数字一起放进同一个深棕胶囊

经验条只显示具体值 `x/y`（不再显示百分比），条内填充仍按经验比例。

### 升级奖励面板

`State.gainExp` 的每一条升级记录带 `level / power / agility / speed / hp`，以及随机领悟的 `reward / rewardId / rewardKind`。`upgradeReward(ups)` 按参考图 `references/new/13401b861367adab44aede056.webp` 渲染奖励面板：

- 顶部用原版「升级奖励」贴图牌（`resource_10-3`）压在面板上沿；
- 一排属性卡片：图标 + 属性名增量（`力量+1` / `敏捷+3` / `速度+2` / `生命+7`）。图标直接复用已按属性配色的道具图（`prop-3` 力 / `prop-4` 敏 / `prop-5` 速）；原版没有单独的「生命」图标，用同风格的圆形「命」字徽补位；
- 本次还领悟了新武器/技能时，再多一张卡片显示该武器/技能的原版图标与名称（如「绝对防御」「木剑」）；
- 卡片边框按属性着色（力红 / 敏蓝 / 速绿 / 命粉），末尾标注「升到 N 级」。

战斗结果、关卡战果、竞技场结算与抽奖奖励都已改用这个面板（`upsHtml()`；关卡那段在 `js/classic-ui.js` 内保留一份 `stageUpsHtml()`，使 `tools/test-stages.cjs` 只注入任务回调代码时也能运行）。主角用原版 `mainWalk1`（88 帧循环跑动）在首页循环播放，帧推进由 `Main.homePlayer()` 的播放器负责，绘制在 `UI.drawActor` 的 490×307 盒子里；这个盒子按毛发重心左移了 115px（`x:224`），让跑动中的松鼠视觉上落在画面中间。

二级界面分页按钮里的 `‹` `›` 字形墨迹相对按钮中心偏低 6px（52px 圆钮；`line-height` 改成 1 也无效），改成 `box-sizing:border-box` 下的 `padding-bottom:23%` 把内容盒上移，箭头才在圆钮里真正居中。

**方天画戟图标**：`images/classic/icons/weapon-1-classic.png` 取自截图 `162315` 的武器界面。该截图把弩戟右刃切在格子边界上（原提取脚本的多边形右边界 x=362 正好落在这里），所以图标右刃末端是齐平的。已核对 `images/classic/reference-cards/weapon-1.png` 与 `images/wuqi.png`：前者完整但下半被红色「真」印章盖住，后者风格不同（带黄色描边）。格子内可用像素到 x=362 就结束了，补全只能凭空造像素，因此这里保持原样未作修补。

### 音量

系统页新增「音乐音量」连续滑块（0~100%），拖动即时生效：

- `Main.setVolume(0~1)` 写入 `localStorage` 的 `ssdz_music_volume`；`全部音量 = BASE_VOLUME(0.35) × 滑块值`。
- 拖到 0 等同静音（同步 `ssdz_music_muted`），再拉回来自动取消静音；原来的「音乐：开/关」按钮仍可一键切换。
- `js/main.js` 里的 `volume` 变量在 `playBgm` 之前初始化，`--` 旧存档没有该键时默认满音量。

### 师徒系统

对照参考设定重做了 `js/classic-extras.js` 的师徒页，并在 `js/state.js` 里把数据与规则实现为可测试的接口：

- **拜师自动学会师父驾到**：`State.setMaster()` 会调用 `learnSkill(13, 1)`，自动学会「师父驾到」（已有则不重复添加）；该技能不受武器/技能总数上限限制。技能 13 的效果（恢复师父等级 ×4 生命、下次攻击必中）已在 `js/sim.js` 里实现。
- **师父数据完整**：`master` 保存等级、四维、武器与技能，界面上点候选卡片即可查看。
- **徒弟日贡**：单机模式下每个徒弟每天产出 `等级 × 3 + 5` 点经验（`apprenticeDailyExp`），师父点「领取日贡」一次收齐；徒弟自己的经验不减少，每个徒弟每天只能领一次（`lastExpDate`）。
- **收徒上限**：`apprenticeCap(level)` —— 10 级前 1 个、10-19 级 2 个、20 级以上 3 个。
- **徒弟数据完整**：`addPrentice(foe)` 记录姓名、等级、四维、武器/技能与入门日期，页面上可查看每个徒弟的属性与今日日贡。
- **师父随机与刷新**：`rollMasterCandidates()` 在玩家等级 +2~+12 级范围内随机，界面上有「刷新师父」，成员带完整属性与装备。
- **可选徒弟与刷新**：「可收服的徒弟」列出 3 位候选人（可刷新），先查看属性再决定，点「收徒挑战」打赢后才收下。
- **解除关系**：徒弟主动退师门花 20 金松果（已学会的技能保留）；师父每天只能踢 1 个徒弟（`canKickToday` / `masterKickDate`）。
- 师徒页用「我的师父 / 我的徒弟」两个页签分开，避免内容超出棋盘被裁切。

旧存档只有 `{name, level}`，`normalizeSave` 会自动补齐四维/武器技能/日贡字段。

`js/classic-extras.js` 一度因编码意外损坏，现已用 `tools/rebuild-extras-1.py`、`tools/rebuild-extras-2.py` 重建：脚本以纯 ASCII + `\uXXXX` 转义写出源码，不再受控制台代码页影响。修改该文件时请直接编辑生成脚本后重跑，或至少避免用 PowerShell 的 `Get-Content` / `Set-Content` 对它做文本替换。

## 调试面板

`js/debug.js` + `css/debug.css` 提供一个开发用调试面板，按 **Ctrl+Shift+D** 或点右上角「调试」按钮开关（Esc 关闭），标题栏可拖动。开关只读写 `localStorage` 的 `ssdz_debug` 项，**不写入正式存档**，点「全部关闭并清除」即可完全恢复。

| 开关 | 效果 |
| --- | --- |
| 无限体力 | `State.consumeEnergy` 不再扣体力，`tickEnergy` 直接回满，进入首页自动补满 |
| 无敌模式 | 战斗模拟里玩家侧最低保留 1 点血（含普攻、反击、自伤与持续伤害） |
| 升级必定成功 | `State.doUpgrade` 不再随机失败 |
| 升级无需消耗 | 升级不扣金松果与卷轴，也不受等级限制 |
| 道具免费 | 商店购买不扣金松果 |
| 关卡不耗挑战书 | 入场与复活都不消耗挑战书 |

一次性按钮：**一键满级**（直接到 60 级并补满升级带来的属性成长）、**一键升级（升1级）**（按正常升级结算一次经验，属性成长与随机领悟照常）、体力全满、金松果 +10000、全道具 +10、全部武器技能满级、解锁全部关卡、重置每日与体力计时。

**彻底重置账号**（红色区域，需点两次确认）会清空存档回到全新开局：等级、属性、经验、道具、装备、关卡进度、战斗记录、师徒与天梯进度全部清掉，**升级过程中随机领悟到的武器与技能也一并消失**。实现方式是清掉 `ssdz_save_v1` 与其 `_backup` 后调用 `State.newGame(name)`，由 `NEW_PLAYER` 重建（`weapons: ['1:1']`、`skills: []`），因此「1 级时随机得到的武器/技能」不会残留。

上面的「开局武器」下拉可以选择重置后用哪把武器开局：

- **原版：方天画戟**（默认）——沿用 `NEW_PLAYER.weapons`，与原客户端一致
- **随机一把**——从原版武器表（`State.weaponList()`，17 把）里随机挑一把，仍是 1 级
- 或直接指定任意一把武器

开局武器通过 `State.newGame(name, { weaponId, weaponLevel })` 写入，不改动技能（技能始终为空）。

其它模块只需调用 `Debug.enabled('键名')`，未加载 `js/debug.js` 时这些调用一律返回关闭，游戏行为与改动前完全一致（Node 回归测试即运行在这种状态下）。

竞技、天梯、好友及师徒等内容为离线模拟。没有连接原游戏服务器，也不提供真实玩家对战、在线排行或社交服务。

关卡流程已按原始 `Mission` 校对：10 级开放，三个高手各六关、依次解锁；每轮连续挑战三名对手，入场消耗一本挑战书，最多复活两次，每次另消耗一本挑战书。整轮经验与金松果总奖励沿用原客户端可确认的数值。原服务器的掉落概率和三战奖励拆分无法恢复，因此碎片采用离线掉落概率，经验与金松果在三战全部通关时一次发放。

## 素材来源与还原边界

经典界面的主要依据是 `references/` 中的用户截图，以及 [references/web/sources.json](references/web/sources.json) 记录的网上截图。基础松鼠、狂战松鼠、师父、经典关卡肖像、部分按钮与卡片由参考图裁剪、清理或重建，来源分别见 [素材清单](images/classic/manifest.json) 和 [参考图细节清单](images/classic/reference-details.json)。裁剪卡片中的灰色、选中和“真”标记属于各自截图状态，不能直接作为所有等级的通用素材。

`E:/squirrel fight1/uc松鼠大战电脑版 PC版/h5ssdz_9game_4230.apk` 内的 `assets/game.zip` 提供了原始 JavaScript、图片、音频和数值表。已经核对：其中的图片与音频在本项目中均有对应文件；旧帧表里的部分资源名称在 APK 本身也不存在，不能据此认定本项目漏拷了整批图片。

目前尚未取得截图对应的经典版完整动画资源或 SWF。因此，经典页面使用静态角色图，战斗继续使用 APK 内的高清角色、NPC、时间轴和特效；村庄背景 [village.svg](images/classic/village.svg) 是依据截图重新绘制的 SVG。界面、数值与可玩流程仍在逐项校对，不能视为原客户端的完整复原。

## 存档

进度保存在浏览器 `localStorage`，正式存档键为 `ssdz_save_v1`。系统页面可导出 JSON，也可导入备份；导入前会确认，并将已有存档保留到当前存档键的 `_backup` 项。旧存档会补齐新增字段，保留已有养成进度。

不同浏览器、地址或端口拥有各自的存档。迁移时请先导出，再在目标地址导入。音乐开关使用独立偏好 `ssdz_music_muted`。

所有测试入口使用 `ssdz_test_save_v1`，与正式存档隔离。测试入口之间共用这份测试存档，可能互相重置测试角色。

```powershell
node tools/test-state.cjs

```

状态回归覆盖存档、属性、道具、装备及养成等关键行为。战斗回归检查命中时机与血量变化、NPC 朝向、武器替换、收招和跳过清理，并把演出截图写入 `tools/research/battle-check/`。扩展玩法回归检查竞技、天梯、抽奖与师徒等本地流程。融合回归覆盖材料选择、校验、扣款与翻页；关卡回归覆盖解锁、三战进度、挑战书、复活、奖励以及中断恢复。

## 代码与研究资料

- `js/orig/`：原始动画、帧表和游戏数值数据。
- `js/engine.js`：图集加载、逐帧动画与绘制；`js/battle.js`：战斗演出；`js/sim.js`：离线战斗计算。
- `js/state.js`：存档、养成、装备、道具与属性结算。
- `js/classic-ui.js`、`js/classic-extras.js`：经典页面与离线扩展玩法；对应样式在 `css/classic.css`、`css/classic-extras.css`。
- `js/debug.js`、`css/debug.css`：开发调试开关面板（Ctrl+Shift+D），详见上文「调试面板」。
- `tools/research/headless-shot.cjs`：本地验证工具，用无头 Chrome/Edge 打开指定页面截图，并取回页面里的 `window.__report` / `window.__home`，用于核对界面像素与布局；`--then <url>` 可在同一会话里再打开一个页面，用于验证跨刷新的持久化。
- `js/classic-fusion.js`、`css/classic-fusion.css`：经典装备融合页面、材料选择及结果展示。
- `js/main.js`：启动、首页、战斗调度及浏览器自检；`js/ui.js` 保留基础 UI 能力。
- [原始客户端研究记录](tools/research-original.md)：版本区别、图集索引、原始代码位置、在线搜索结果与证据限制。
- `tools/research/original/`：从 APK 提取的原脚本；`tools/research/original-ui-coordinates.json`：静态贴图调用索引，含条件分支和弹窗，并非一张完整画面的坐标表。
- `tools/extract-ui-assets.py`、`tools/extract-classic-reference-details.py`：素材导出与参考图清理脚本，需 Python/Pillow；前者还需 Node.js 读取原始数据表。
