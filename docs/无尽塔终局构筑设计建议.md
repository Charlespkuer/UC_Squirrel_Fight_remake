# 无尽塔终局结构设计建议：从「清单」到「构筑」

> 起因（用户口径）：不希望再要数值平衡公式，而是想解决**池子与商店在运营设计上的终局问题** ——
> 每一局最后都会变成"在商店里刷终焉烙印"，体验同质化，体现不出差异；
> 并且希望能存在一种**能对抗敌方类指数增长的我方构筑，但不能容易凑出来**。
>
> 本文只谈**结构**：为什么现在必然收敛、要引入哪些**新的机制形态**、每一条怎么落地、怎么验收。
> 不含"把某个系数从 0.2 改成 0.15"这类数值建议。

---

## 0. TL;DR

1. **现在的池子是一张"清单"**：有限件是清单（掏空即结束），无限件是几条纯数值管道（C26-C29 加法、C49 线性）。
   清单 + 加权随机 + 5 个永久槽 + 一条"定时发同一个传奇"的保底 = **收敛是数学上的必然**，不是概率问题。
2. **现有运营机制全都在"降低方差"，没有一个在"创造身份"**：reroll（再抽同一分布）、折扣、免费刷新、
   同稀有度交换、保底、铸币赠品 —— 它们让"抽到什么"更公平，但完全不改变"我在造什么"。
   所以差异只能来自运气，而运气在长局里会被平均掉 → 每局终局长一个样。
3. **要对抗指数，我方也必须有一条指数通道 —— 但必须由"组合 + 条件 + 代价"生成**，
   而不是某一颗弹的数值。建议的核心结构是 **引擎 × 燃料 × 共鸣**：
   引擎定义通道形状（稀少、互斥），燃料提供触发原料（常见、可无限），
   三件同族才把"线性"解锁成"乘法"。
4. **保底要改向**：把"每 120 格强制发一件传奇（2/3 是 C49）"改成"发一张**传奇自选券**"。
   这是本方案里**性价比最高的一步** —— 它直接把当前最大的收敛器变成构筑补完工具。
   （坦白说：这条保底是我上一轮按"稳定出率"的思路加的，从多样性角度看方向是错的。）
5. 落地顺序：**自选券 + 定向搜索（低风险、立竿见影）→ 誓约/流派（身份）→ 引擎×燃料×共鸣（指数构筑）→ 敌方侵蚀扩展（代价）→ 变异池（让池子永不枯竭）**。

## 1. 结构性诊断：同质化是怎么被"设计出来"的

### 1.1 池子形态：清单 vs 系统

| 现状 | 后果 |
| --- | --- |
| 有限件是**一次性清单**（拿到就没了 / 达到 maxStacks 就出池） | 中后期池子开始**变空**，剩下的候选越来越少 |
| 无限件只有**纯数值管道**（C26-C29 加法、C49 线性终乘） | 只有 C49 具备"能跟指数对话"的形状 → **所有构筑都指向它** |
| 永久槽位是**数量上限**（`PERMANENT_SLOTS = 5`），不是**互斥阵营** | 最优策略恒为"把当前最强的装上/替换" → 终局配置趋同 |
| 池子里 77 件、其中 6 件是运营类 | 运营件**稀释**了池子，却在极端情况下变成"死格子"：既不加成长，也不加身份 |

**关键**：清单式池子的终局一定是"清单被读完"。玩家不是在**构筑**，而是在**清空列表**。

### 1.2 运营机制：只有"降方差"，没有"造身份"

| 机制 | 它做了什么 | 它**没有**做什么 |
| --- | --- | --- |
| 刷新（reroll，10→70 币） | 用钱换更多次同一分布的抽样 | 不让玩家表达"我要什么" |
| 折扣（E04）、免费刷新 | 提高单位币的抽样次数 | 不改变抽到的内容结构 |
| 同稀有度交换（铸币商店） | 给一次"等值替换" | 不产生流派或方向 |
| 传奇保底（`LEGEND_PITY`） | **定时**发同一件（2/3 是 C49） | 不给选择 → 反而**加速收敛** |
| 赠品/铸币 | 额外的获取次数 | 同上 |

**结论**：现有运营设计的共同目标是"让随机更公平"。但在 roguelike 里，
**公平的随机不等于有差异的体验** —— 差异来自"我做了什么承诺、放弃了什么"，而现在**没有任何不可逆的承诺**。

### 1.3 缺少的三样东西

1. **承诺（Commitment）**：没有任何机制让玩家"锁死一条路、放弃另一条"。没有承诺 → 最优解唯一。
2. **组合（Combination）**：没有"只有凑齐才生效"的机制 → 每件都独立生效 → 强弱线性可加 → 终局只剩排序。
3. **风险（Entropy）**：指数通道如果存在却不承担风险，就会变成新的唯一解。
   现在唯一的侵蚀机制是"30 层后每 2 层作废一条**已损毁**烙印"（`loseRandomBrokenMark`），
   它只作用于烙印，且只是**惩罚**，没有被设计成"可对抗的博弈"。

## 2. 目标：让"终局"重新变成"构筑"

### 2.1 结构指标（不是数值指标）

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 终局核心件**种类**分布（分布熵） | 恒为 1 种（C49）→ 熵 ≈ 0 | ≥ 3 种，熵 ≥ 1.5 bit |
| 同练度、不同构筑的**通关层数方差** | ≈ 0（都卡在同一处） | 标准差 ≥ 5 层 |
| 每局**不可逆决策**数 | 0 | ≥ 1（誓约/引擎/共鸣三选一） |
| **指数通道**达成率 | 不存在 | 5%~15% 的局能凑齐（"不容易但可行"） |
| 商店里"玩家定向"格占比 | 0% | ≥ 20% |

### 2.2 设计原则

1. **强度来自组合，不来自单件**：允许指数，但必须"三件套 + 条件"才能解锁。
2. **差异来自承诺，不来自运气**：每局至少一次不可逆的方向选择。
3. **随机只决定节奏，不决定身份**：玩家能影响"看到什么类别"。
4. **指数必须可被针对**：敌方机制能拆引擎 → 高收益伴随高风险。
5. **池子永不枯竭，但内容在变**：掏空后是**演化**，不是空。

## 3. 核心改造（六个结构，按落地顺序）

### 3.1 【先做】保底改成「传奇自选券」

- **现状**：`LEGEND_PITY` 累计到 120 格 → 强制传奇档 → 按 `pityWeight` 加权输出传奇
  （C37 与 C49 已于 2026-10 调回 **1:1**，不再定向偏向 C49）。
  这是一个**收敛器**：它保证每个人最后都在同一条管道上。
- **改成**：累计到阈值 → 发放 1 张**「传奇自选券」**（可叠加），在商店界面里**任选池内一件传奇**。
- **效果**：
  - 想要 C49 的拿 C49；想转引擎的拿引擎件；想补烙印套的拿 C37 → **保底变成构筑补完工具**。
  - "刷不到某件"不再是不可控的运气问题，而是"你攒了几张券、用在哪个缺口"的决策。
- **附带**：券可以跨层累积、可以在深层"用 2 张换一件已出的变异件"（与 3.4 联动）。
- **改动面**：`rollOneCandidate` 里的"强制档"换成"发券"，商店 UI 加一个自选面板。**不动任何数值**。

### 3.2 【做】商店从「再抽一次」改成「定向搜索」

- 把 reroll 的语义从"重抽 5 格"改成"**先选类别，再抽 5 格**"：
  类别由当前构筑动态给出（成长 / 烙印 / 机制 / 运营 / 共鸣件），价格随层数下降（越深越能定向）。
- 效果：玩家的"我要造什么"能**反馈**到"我能看到什么"。运气从"身份"挪到"节奏"。
- 复用：`rollShopSlots` 的候选过滤、`dynamicTierWeights`、`weightDivBy` 都是现成钩子。
- 与 3.1 配合：券负责"补缺"，搜索负责"推进方向"。

### 3.3 【核心】把增益分成三类：引擎 / 燃料 / 共鸣

这是"能对抗指数、但不容易"的**唯一可行结构**。

| 类别 | 稀有度 | 数量 | 作用 | 获取 |
| --- | --- | --- | --- | --- |
| **引擎（Engine）** | 传奇 | 每局 1~2 件 | **定义通道形状**（不是数值）：决定"什么事件会带来复利" | 深层 boss / 事件 / 自选券（商店买不到全部） |
| **燃料（Fuel）** | 普通~史诗 | 多、可无限 | 提供引擎的**触发原料**（烙印、币、空槽、限次件、敌人机制…） | 商店、战斗奖励 |
| **共鸣（Resonance）** | — | 3 件一套 | **只有凑齐 3 件同族**，引擎才从"线性"升级为"乘法" | 必须跨池收集（商店/ boss / 事件各一件） |

- **为什么这样能对抗指数**：乘法通道的形状与敌人一致（复利），所以"追得上"在数学上成为可能。
- **为什么不容易**：
  1. 引擎稀少且**互斥**（一局只能选一条，选错不能回头）；
  2. 共鸣必须**跨池**收集（商店只出其中一件，其余要去 boss/事件拿）；
  3. 燃料要**主动经营**（例如"主动让烙印碎掉"这种反直觉操作）；
  4. 通道**会被敌人侵蚀**（3.6）。
- **为什么不会变成新的唯一解**：不同引擎的收益曲线不同（有的前期强、有的需要 40 层才起飞），
  且**互相排斥** → 一局只能选一条 → 每局的终局核心件天然不同。

#### 三个示例引擎（各自是一个"构筑身份"，形状不同、代价不同）

**A. 噬印者（熵流）——"把失去变成复利"**

| 项 | 设计 |
| --- | --- |
| 引擎 | 每有 1 枚烙印**损毁** → 终乘 ×(1+r) 永久累加，并立刻补发 1 枚同族烙印 |
| 燃料 | 普通烙印（C39-C44）、终焉烙印（C49）、涌泉（C52）、淘金（C53）、"提高损毁概率"类 |
| 共鸣 | 引擎 + 任意两件烙印类 → **30 层后的"作废已损毁烙印"变成"再补一枚"**（把敌方侵蚀反转成燃料） |
| 代价 | 每层固定流血，流血随损毁数上升；永久槽 -1 |
| 为什么难 | 损毁是 6% 概率的**不可控事件** → 必须先用共鸣/燃料把损毁率提上去，且要熬过"还没起飞"的中期 |
| 被针对 | 敌人的**吞噬**机制改为"吃掉你 1 层引擎层数" |

**B. 虚室生白（极简流）——"空着比装满更强"**

| 项 | 设计 |
| --- | --- |
| 引擎 | 每个**空着的永久槽** → 全属性 ×(1+r)（与"装满"完全相反的收益方向） |
| 燃料 | 虚空铭文 C37（附魔空出槽）、`sacrificePerm`（主动放弃已装的永久增益）、提高槽位上限的件 |
| 共鸣 | 引擎 + 2 件"空槽/附魔"类 → 空槽数同时提升**商店质量**（反向降权） |
| 代价 | 不能安装任何永久增益 → 前中期极度脆弱，必须靠机制/操作活下来 |
| 为什么难 | 要求玩家**主动放弃已经拿到的强力件**（不可逆），且反向利用"槽位"这个既有资源 |
| 被针对 | 环境词缀"贪欲"：接下来 N 层禁止放弃/替换增益 |

**C. 钱生钱（商贾滚雪球）——"不花钱才是最强"**

| 项 | 设计 |
| --- | --- |
| 引擎 | 试炼币**余额本身**提供乘法成长（余额越厚，全属性乘区越大），且跨层不清零 |
| 燃料 | 门庭若市 C59、折扣 E04、讨价还价 E14、铸币商店的免费交换、挥金如土 C36、豪掷千金 C58 |
| 共鸣 | 引擎 + 2 件经济件 → 刷新/定向免费，且"买一件"不再清零复利基数 |
| 代价 | 一旦购买限次件就断复利（买 = 重置换算）→ 战斗全靠机制与操作 |
| 为什么难 | 前期必须"忍住不花钱"熬过去，牺牲大量即时战力；对操作与信息要求最高 |
| 被针对 | 环境"通胀"（每层按比例扣币）、敌人"掠夺"（胜利也扣币） |

> 三条引擎的收益曲线分别偏"中期起飞 / 全程稳定 / 后期爆发"，
> 互斥 + 不同曲线 → 玩家每局都要重新判断"这一局我能不能起飞"，而不是重复同一次操作。

### 3.4 【做】变异池：掏空不是结束，而是演化

- 有限件达到获取上限后**不再消失，而是变异**成"同主题、不同取舍"的版本进池：

| 原件 | 变异（示例） | 代价 |
| --- | --- | --- |
| 终焉烙印 | 「·裂」：终乘更强 | 每层固定流血 |
| 涅槃 | 「·烬」：复活 +1 次 | 复活后本层全属性 -30% |
| 磐石之躯 | 「·顽」：上限更高 | 治疗效率 -50% |
| 战斗续航 | 「·竭」：回血更多 | 每场开战先扣 10% 血 |

- 解锁条件与"原件的获得次数/层数"挂钩 → **你越用某条线，它越会演化**，而不是"堆同一件"。
- 效果：`极端情况` 下池子永远有东西，但**内容在变** + 每件变异都带取舍 → 差异而非重复。
- 这是**替代"数值堆叠"的主要手段**：成长感来自"新的取舍"，不来自"更大的数字"。

### 3.5 【做】誓约：每局的"我是谁"

- 开局（或每 10 层一次机会）**三选一誓约**，作用是**改变池子与商店结构**，而不是给数值：

| 誓约 | 正面 | 排他/负面 |
| --- | --- | --- |
| 烙印主 | 烙印类出现率与叠层上限大幅提升 | 永久槽 -2；运营类**完全不出现** |
| 商贾 | 币收入/折扣/免费刷新/定向价格极低 | 限次件获取上限减半；烙印类不出现 |
| 吞噬 | 可把"不要的增益"转化为成长（献祭/转化） | 每层流血；环境强度提升 |
| 精算 | 永久槽 +2；可定向搜任意类别 | 传奇档不出现；自选券作废 |

- 目的：让"我这一局是什么"决定"我能看到什么" → **从根上排除一部分最优解**，
  使得"每局都收敛到同一配置"在结构上不可能。
- 复用：现有池过滤（`poolFilter`）、`weightDivBy`、`permSlots`、`coinMul`、`ENV_CHANCE` 都是钩子。

### 3.6 【做】敌方侵蚀：让指数通道"可被针对"

- 已有：30 层后每 2 层作废一条**已损毁**烙印（`loseRandomBrokenMark`）。
- 扩展成三种**可读、可对抗**的反击：

| 反击 | 形式 | 玩家的应对 |
| --- | --- | --- |
| 吞噬（改 `devour`） | 吃掉你 **1 层引擎层数**（不再只是给自己加攻） | 留"备用燃料"、提前攒冗余 |
| 封锁（新环境词缀） | 接下来 N 层**某类增益无效**（烙印/经济/附魔…） | 准备双通道/转型 |
| 掠夺 | 胜利也扣币/扣券 | 商贾流必须留安全垫 |

- 关键：反击必须**提前预告**（写在进层情报里），否则是"随机惩罚"而不是"博弈"。
- 这样指数引擎**不是免费的强大**：凑齐难、维持更难 → 满足"不容易实现"。

### 3.7 【可选】运营类增益的"出口化"

- 现状：运营件在极端情况下变死格子。建议给每条运营线一个"后期出口"：
  运营件可以**献祭成引擎燃料**，或在誓约下转化为该流派的核心资源。
- 这让"运营类"从"稀释池子的噪音"变成"不同流派的燃料"，而不是数值。

## 4. 与现有代码的对接（钩子清单，说明可落地）

| 需要的能力 | 现成钩子 |
| --- | --- |
| 池子过滤 / 权重 / 定向 | `poolFilter`、`weightDivBy`、`dynamicTierWeights`、`rollShopSlots`、`rollChoices` |

| 侵蚀 / 作废 | `loseRandomBrokenMark`、`brokenMarks`、`rebuildFragileTotals` |
| 敌方机制 | `mech`（thorns / regen / lifesteal / shell / devour）+ 环境词缀 `envModTotal` |
| 经济 | `COINS`、`SHOP`（reroll）、铸币商店 `MINT_SHOP`（含免费交换） |
| 变异件 | 现有数据驱动（`BUFFS` + `tags` + `mods`）可直接新增同族变体 |

## 5. 落地顺序（按"性价比 / 风险"排序）

| 步骤 | 内容 | 为什么先做 | 风险 |
| --- | --- | --- | --- |
| **1** | 保底 → 传奇**自选券**（3.1）+ 定向搜索（3.2） | 直接杀死"每局都刷 C49"的**直接原因**，改动小 | 低（UI + 发券逻辑） |
| **2** | **誓约**（3.5），先做 2 条（烙印主 / 商贾） | 制造"每局不同"的身份，验证玩家是否买账 | 中（需要池子分组与 UI） |
| **3** | **引擎 × 燃料 × 共鸣**（3.3），先做 1 条引擎（噬印者） | 验证"指数通道不容易但可行"的手感 | 中高（新机制 + 平衡观察） |
| **4** | **敌方侵蚀扩展**（3.6） | 给指数通道代价，防止变成新唯一解 | 中（需要预告/情报 UI） |
| **5** | **变异池**（3.4） | 让池子永不枯竭、内容持续演化 | 中（数据量增加） |
| 6 | 运营件出口化（3.7） | 收尾，让运营类融入流派 | 低 |

> 注意：**1 和 3 是"必须"，2/4 是"让 3 播得开"的配套**。
> 只做 1 会让终局从"C49 单解"变成"自选券单解"；只做 3 而没有 2/4，引擎会成为新的唯一解。

## 6. 验收（结构指标，可直接统计）

| 指标 | 怎么测 | 目标 |
| --- | --- | --- |
| 终局核心件熵 | 统计每局 40 层后的"核心件"分布，算香农熵 | ≥ 1.5 bit（现在 ≈0） |
| 构筑相关性 | 固定练度、抽样 100 局，统计通关层数标准差 | ≥ 5 层（现在 ≈0） |
| 不可逆决策 | 每局誓约/引擎的实际选择次数 | ≥ 1 |
| 指数通道达成率 | 凑齐"引擎 + 3 件共鸣"的局占比 | 5%~15% |
| 定向格占比 | 商店里由玩家定向产生的格数 / 总格数 | ≥ 20% |
| 保底用途分布 | 自选券花在哪一类（成长/烙印/引擎/变异） | 前三类都应有可观占比（不是单峰） |

## 7. 一句话总结

把池子从**"一张会被读完的清单"**改成**"引擎 × 燃料 × 共鸣 的组合系统"**，
把运营机制从**"降低方差的公平工具"**改成**"制造承诺与定向的手段"**，
再把唯一的收敛器（保底）从**"定时发同一件"**改成**"给玩家一次选择"** ——
指数构筑才会"存在但不容易"，每局的终局也才会长得不一样。
