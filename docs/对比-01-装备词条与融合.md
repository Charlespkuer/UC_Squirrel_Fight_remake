## 1.3 装备主属性：**结构性差异（最重要）**

### 原版：288 件装备各自带属性点

`equipsArray`（`MainMovie.as:19142`，**288 条**）字段：
`setId, quality, group, level, price, id, agile, power, hp, speed, type, name, frame`

```
setId q  lvl price id  agile power hp  speed type  name
1     0  5   55    1   1     0     0   0     0     斗斗头巾
1     0  5   55    2   0     1     0   0     1     斗斗手套
1     0  5   55    3   0     0     7   0     2     斗斗服     ← 生命 = 敏捷 × 7
3     1  12  55    9   3     0     0   0     0     格斗头巾
3     1  12  55    11  0     0     21  0     2     格斗服
6     2  16  55    21  6     0     0   0     0     格斗头巾
6     2  16  55    23  0     0     42  0     2     格斗服
```

规律：**头巾→敏捷、手套→力量、衣服→生命（同组敏捷 × 7）、鞋→速度**；数值随品质阶梯上升。

### 新版：同部位共用 `gearMap.abilities` 的一位

```js
// state.js:1102
const abilityVal = parseInt(g.abilities.split(',')[type]);
// state.js:1425-1430
let val = gi.abilityVal;
if (gi.type === 0) agility += val;
else if (gi.type === 1) power += val;
else if (gi.type === 2) hp += val;
else speed += val;
```

> ⚠️ **差异 2（影响面最大）**：原版**每件装备有独立数值**（同是"蓝色衣服"，不同组数值不同）；
> 新版**同部位共用同一个值**，装备之间只有名字/等级/词条差异。
> **这直接削弱了"刷装备"的意义** —— 换一件同名装备，主属性完全一样。
>
> **建议**：补一张 288 条的 `equipsArray`。数据可从原版直接抽取，**零设计成本，收益极高**。

## 1.4 词条（附加属性）

### 原版 `attachmentArray`（`MainMovie.as:19143`）：48 条 × 5 列

| 列 | 含义 |
|---|---|
| 0 | id |
| 1 | **星级数值**，3 档（`3,6,10`）→ 由**星级 level(1-3)** 选取 |
| 2 | **额外值档位**，12 档（`1..12` / `1.25,2.50,...` / `2.5,5,...`）→ 由**计数 count(1-12)** 选取 |
| 3 | 名称模板（`空手暴击伤害+N%`） |
| 4 | 后缀（`+N%`） |

取值链（`getAttachment()` `L162`）：

```actionscript
_loc2.ability    = 列1.split(",")[int(level - 1)];   // 星级
_loc2.extraValue = 列2.split(",")[index];            // index = count - 1
_loc3 = 列3.split("N");
des   = _loc3[0] + extraValue + _loc3[1];            // 名称模板填值
```

**装备实例字段**（协议串 `player.equips`，`L910-940`）：
`gearId : isWear : key : stoneId : addr1 : addr1Lv : count1 : addr2 : addr2Lv : count2 : addr3 : addr3Lv : count3`
即**最多 3 条词条，每条带「星级 + 计数」**。

`count1/2/3` 由服务端返回的 `alphaPoint/betaPoint/gammaPoint` 更新（`updateExtra()` `L4070`）——
**鉴定（identify）就是在推这个计数。**

**示例词条摘选**：

| id | 星级数值 | 名称模板 |
|---|---|---|
| 1 | 3,6,10 | 空手暴击伤害+N% |
| 5 | 5,9,14 | 空手伤害+N% |
| 12 | 12,24,48 | 方天画戟伤害+N% |
| 27 | 20,40,80 | 力王附体效果提升N% |
| 40 | 2,3,4 | 来点松果补血提升N倍 |
| 47 | 5,15,30 | 绝对防御效果提升N% |
| 49 | 8,14,22 | 基础反击率效果提升N% |

数值档位分布：`3,6,10`(11条) / `10,20,40`(10条) / `10,20,30`(6条) / `20,40,80`(5条) / `8,16,32`(4条) /
`12,24,48`(3条)，其余 9 种各 1 条（含 `2,3,4`、`40,80,120` 等）。

### 新版：丢掉"计数"维度

`attachmentMap` 只有 `id, ability, name` **三列**；`normalizeExt()` 只保留 `{id, level}`，
`level` 上限 **3**（`state.js:1094`）。

> ⚠️ **差异 3**：新版**丢掉了计数维度**（原版 `count1/2/3` 与 12 档额外值）。
> 原版词条可成长 12 档，新版 3 星封顶，**成长空间与"鉴定"玩法一并消失**。

**原版各品质的词条数量/星级上限**（新版注释自述，`state.js:2374`）：
白绿**无词条**、蓝装 **1 条且最多 2 星**、紫装 **2 条且最多 3 星**；橙/黑装 3 条（见 1.5 继承规则）。

## 1.5 融合（`mergeGear.do`）

### 官方规则原文（`MainMovie.as:19521`，最权威口径）

> 1、放入 3 件**指定颜色**的装备作为融合材料，融合成功可得到 1 件高级装备。
> 2、合出的装备**名称和部位**在融合材料中**随机选择 1 个做继承**。
>    例如要融合 1 件紫装，材料分别为蓝色犀牛鞋、诅咒服、诅咒服，
>    那么融合出紫色犀牛鞋的几率约为 **1/3**、融合出紫色诅咒服的几率约为 **2/3**。
> 3、**附加属性的继承规则**——合紫装：选择 **2 条星级相对最高**的附加属性；
>    合橙装/黑装：选择 **2 条星级相对最高**的附加属性，**再在剩余属性中随机选择 1 条**。
>    建议不要在材料中放入多条同类附加属性，以免合出重复属性导致浪费。
> 4、融合时**有几率提升附加属性的星级**。
> 5、融合**紫装、橙装、黑装**时有较低几率出现**深海、机器猫、怒战、狂战**等装备。

### 服务端参数与费用

- 请求：`mergeGear.do?gearOne=&gearTwo=&gearThree=`（`L3990`），传装备 **key**
- 费用（`L8149-8191`，`composeCost` 默认 `200`，`L19653`）：

| `composeType` | 材料 → 产物 | 界面文案 | 费用 |
|---|---|---|---|
| 1 | 蓝 ×3 → 紫 | 仅显示未穿的蓝装 | **200**（`activity_temp=="true"` → **100**） |
| 2 | 紫 ×3 → 橙 | 仅显示未穿的紫装 | **200**（`orange=="true"` → **0**） |
| 3 | 橙 ×3 → 黑 | 仅显示未穿的橙装 | **200**（`orange=="true"` → **0**） |

- 前置：**等级 > 19**（`chooseEquipWin()` `L8328`），未穿材料 ≥ 3 件（`L8330`）
- 产物词条槽位：`composeType 1 → 2` 槽；`2/3 → 3` 槽（`L8162/8176/8190`）

### 新版实现（`state.js:1317-1357`）

```js
if (S.goldPoint < 50) return { ok:false, msg:'融合费用不足（50金松果）' };
if (q >= 3) {                                          // 3 件紫 → 该部位随机橙
  const pool = gearIdsOf(part, 3);
  const ext = Object.keys(best).slice(0, 3).map(...);  // 取各词条最高星，截前 3
  inst.orange = true;
} else {
  const candidates = gearIdsOf(part, q + 1);            // 同部位、品质 +1
  addGear(pick(candidates), q+1>=2 ? randomExt(...) : []);
}
```

`classic-fusion.js` 界面校验：需 3 件、同部位、同品质、未穿戴、未加星标、非传说，费用常量 `COST = 50`。

### 逐项对比

| # | 项目 | 原版 | 新版 | 影响面 |
|---|---|---|---|---|
| 1.5.1 | 费用 | **200**（活动 100 / 橙主材料 0） | **50** | 数值（便宜 4 倍） |

> 但去掉原版三个核心乐趣点：**名称/部位继承的赌博感**、**词条升星**、**稀有装备掉落**。
> 费用从 200 降到 50 也削弱了金松果消耗需求。

## 1.6 词条获取三途径：融合 / 鉴定 / 镶嵌

### ① 融合 —— 见 1.5

### ② 鉴定 `identify.do`（`L4017-4037`）—— **新版完全缺失**

```actionscript
setState(100);
var _loc2 = baseUrl + "flash/identify.do?gearKey=" + equip.key;
```

- 费用：**5 金松果**（`getMyPropById(8).count -= 5`，`L4025`）
- 成功后服务端返回 `alphaAtt/alphaLevel`（或 `alphaPoint/betaPoint/gammaPoint`），
  经 `updateExtra()` 写入 `addr1/addr1Lv/count1...`（`L4070-4085`）
- 可能同时回传 `power/agility/speed/hp` 总值并刷新状态面板

> ❌ **差异 4**：新版**没有鉴定**。原版这是给装备"洗/加词条"的核心途径 ——
> 因为原版词条有 12 档计数，鉴定就是推这个计数的口子。新版删掉计数维度后，鉴定也一并没了。

### ③ 镶嵌 `inlay.do`（`L3993`）+ 拆宝石 `tear.do`（`L4038`）

**原版**：

- 请求 `inlay.do?gearKey=&propId=`，成功后 `equip.stoneId = stone.id`
- **只有 `quality > 3`（橙/黑）才能镶**（`doShowEquipInfo()` `L7908`）
- 显示时若 `stoneId > 100`，加 `" +" + getPercentById(stoneId) + "%"`（`L7948`）
- 宝石道具（`propsArray` `L19137`）：**101 一级 … 107 七级宝石**，
  说明统一为"镶嵌到橙装后，提升装备属性点 X%，并提升附加属性效果。"
- **主属性加成曲线**（`getPercentById()` `L45`）：`5 × (n² − n + 2)`，`n = stoneId − 100`
- 拆宝石：**5 金松果**，宝石放回背包

| 宝石 | 原版加成 | 新版（`gemLevel×4`） | 倍数 |
|---|---|---|---|
| 1 级 | **+10%** | +4% | 2.5× |
| 2 级 | **+20%** | +8% | 2.5× |
| 3 级 | **+40%** | +12% | 3.3× |
| 4 级 | **+70%** | +16% | 4.4× |
| 5 级 | **+110%** | +20% | 5.5× |
| 6 级 | **+160%** | +24% | 6.7× |
| 7 级 | **+220%** | +28% | **7.9×** |

**新版**（`socketGem()` `state.js:1259`）：

- 只有 `orange === true` 能镶（等价原版 `quality>3`）✅
- **每件限 1 颗**（`if (g.gem) return '每件装备最多镶嵌 1 颗…'`）
- 主属性 **`lv × 4`%**；附加属性效果 **`lv × (2 + rand(0..2))`%**（可拆后重随）
- 拆卸 5 金松果 ✅ 一致

> ⚠️ **差异 5**：宝石主属性曲线差 **2.5× ~ 7.9×**（越高级差越多）。
> 原版橙装镶 7 级宝石 = 属性点 **+220%**，是后期核心成长线；新版只有 +28%，**宝石在后期几乎无意义**。
>
> ➕ **新版新增**：宝石合成（`mergeGems()` `L1236`，3 个同级 + 10 金松果，成功率 `60/50/40/30/20/10%`，
> 失败 50% 降级）、45 级起掉落（75% 一级 / 25% 二级）。**原版客户端未见宝石合成**（可能在服务端）。
