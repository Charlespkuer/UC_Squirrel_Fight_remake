## 2026-10 第二十三批（`需求143`）：绝对防御的反伤不再「直接反死」——有装死就触发装死

- **用户口径**：被绝对防御反伤打到死线时，只要受击方（出手方）有**装死**，就必须触发装死，
  不能被反伤直接反死。以前反伤只调 `tryDeathSave`（它只认涅槃 / 金蝉脱壳），装死被绕过。
- 新增 `sim.js` 的 `reflectHurt(target, amount, r)`：反伤走**和普通伤害同一条致死保护链**
  （装死 → 涅槃 / 金蝉脱壳 → 调试图腾），触发时装死的老规矩照旧（留 1 血、清眩晕、
  **立刻再行动一次**）。**五种反伤统一走它**：绝对防御、荆棘铁壁、荆棘之甲、镜鳞、沉默之壁
  （后两种以前连复活甲都没走，一并归口）。
- 回放跟着修：新增 `r.fakeDieSide`（谁装的死）与 `r.fakeDieReflect`，`battle.js` 据此把「装死」
  的飘字与动作画在**正确的人**身上 —— 普通受击是挨打的那位，被反伤时是出手的那位
  （否则会顶掉对方的「绝对防御」表现）；多段攻击汇总与反击路径也一起带上这两个标记。
- 反噬豁免优先于装死（免疫反伤的人根本不吃这一下，装死次数留着）；反伤**不吃**攻击方的
  `ignoreFakeDie`（橡皮擦 / 真·方天画戟那类只作用于「挨打方」的装死）。
- 回归：`tools/test-combat-rules.cjs` 的「绝对防御的反伤不再『直接反死』」（`需求143`，一条用例）。

## 2026-10 第二十二批（`需求141`）：真化武技的专属贴图（技能此前完全没有）

- **`images/classic/reference-cards/` 里其实混着两套图**（用户指出「很多真化贴图可以从这里找」）：
  一套是**灰色版** —— 未解锁时显示的那几张，正是代码里 `grey` 名单
  （weapon 2/3/4/7/9/10、skill 3/7/8/9/14/15/18/23）；另一套是**真·版** ——
  右下角盖了红「真」字章的方卡（weapon 1/5/6/8、skill 1/2/4/5/6/10/11/12/13/16/17/24）。
  真·版此前**一张都没被调用**；技能真化更是连通路都没有（`trueForm` 写死 `kind === 'weapon'`）。
  分辨两套图的办法（改素材后要重新对一遍）：看右下角一圈有没有高饱和红像素 ——
  红章图那一块的红像素占比 ≥3%，灰色版是 0%。
- **修法**：`classic-ui.js` 的 `icon()` 最前面加一张 `TRUE_CARD_IDS` 名单 —— 真化且名单里有图，
  就显示 `reference-cards/<kind>-<id>.png`；图鉴与详情弹窗的 `trueForm` 判断去掉
  「只判武器」的限制（武器、技能一视同仁）。没有真·卡面的真武器（11~17）继续走
  `icons/weapon-true-<id>.png`；未真化 / 未拥有的一切照旧（灰色版卡面仍归「未解锁」用）。
- 回归：`tools/test-ui-flow.cjs` 的贴图用例扩写 —— 17 把真化武器逐个断言走哪张图、
  12 个真化技能逐个断言走真·卡面（用户点名的「真·来点松果」单独一条）、未真化/未拥有不受影响、
  `TRUE_CARD_IDS` 与 `grey` 名单里的每张图都必须真实存在（写错 id 会裂图），
  外加两条接线断言防「又只判武器」。

## 2026-10 第二十一批（`需求140`）：绝对防御 —— 投掷类完全不触发 + 抬高二次/多次触发

- **投掷类攻击根本不触发绝对防御**（用户口径，先按"挡得住但弹不回去"实现过一版，用户收紧了）：
  `sim.js` 的 `dmgReduce` 里加 `opts.weaponType !== '投掷'` —— 扔过来的武器**不挡、不反弹**，
  而且**不计入降权计数**（计数只在触发分支里 +1，跳过分支就意味着投掷不会把后续触发率压下去）。
  近战 / 徒手 / 技能照旧（徒手没有武器类型，所以照旧触发）。
  顺手修掉一个连带问题：回合记录里的 `r.jueDui`（战斗动画 `skill_16`、「绝对防御」飘字、
  塔统计的判据）原来只在**有反弹伤害**时才传播，反弹恰好为 0 时整条标记会丢
  （动画不出、统计还会把这次当成实打实的命中），现在改为独立传播。
- **抬高二次与多次触发**（平衡补偿）：`jueDuiAgain` 13 → **17**、`jueDuiDecay` 0.7 → **0.78**、
  `jueDuiMin` 2 → **6**；曲线由 22/13/9/6/4/3/2… 变为 **22/17/13/10/8/6/6…**
  （首次 22 不变；二次 +31%、三次 +44%、地板 2→6 ×3）。
  按 20 回合拉锯、每回合挨一次（且都算非投掷）估算，整场"挡下次数"的期望
  从约 1.63 次升到约 2.38 次（+46%）—— 因为投掷不再触发，实际收益取决于对手的武器构成。
  C33 秘技通神加成后的二次档仍受 45% 封顶（17×3 = 51 → 45），不破「二次及以后 ≤50%」的底线。
- 回归：`tools/test-combat-rules.cjs` 新增「绝对防御：投掷武器完全不触发（不挡、不反弹、也不降权）」
  —— 直接调 `Sim.dmgReduce`（本轮为可测性导出）并把随机流钉成必触发，所以是**确定性**结论；
  既有的触发率曲线用例按新曲线更新（含地板 6、统计口径排除投掷）。
  `tools/test-fixes-round.cjs` 里 `需求57`/`需求66` 写死的旧数值（13 / 27 / 19.5 / 39 / 32.5）
  同步改为 17 / 39 / 25.5 / 45 / 42.5。
- **`docs/真化武器与技能数值.md` 改为按符号名定位**（维护性，用户要求）：那一列原来写
  `sim.js:1234` 这样的行号，每轮改代码都得手工跟着挪（已经连续三轮返工）——现在 33 处全部换成
  符号名 / 代码片段（`mustHit`、`w.id === 12`、`dodgeChance()`、`case 18`…），
  代码怎么挪都不用再动文档；文档里的代码片段都与源码逐字一致（本轮核对过 9 处）。
