# 松鼠大战 · 怀旧单机复刻版

把当年《松鼠大战》的玩法（三侠、关卡、背包装备、竞技场、天梯、挑战塔）做成**纯静态网页**的单机复刻：
没有构建步骤，双击启动器或用任意静态服务器打开 `scripts/index.html` 就能玩。存档写本地文件，
也支持 Mac ↔ Windows 双机同步。经典界面与高清动画来自不同版本，仍有未恢复的素材，不宣称逐像素复原。

## 启动

| 平台 | 方式 |
|---|---|
| macOS | 双击 `启动游戏.command`（停：`bash 启动游戏.command --stop`） |
| Windows | 双击 `启动游戏.cmd` |
| 手动 | `node scripts/serve.js` → 浏览器打开 `http://127.0.0.1:8080/`（端口可改；传 `0` = 让系统挑一个空闲端口） |

> **存档到底在哪**：有本地服务器时，正式存档就是 `save/progress.json`。启动时**磁盘存档永远是第一优先**：
> 只要读得到文件，就一定用它；浏览器 localStorage 只是「连不上本地服务器」时的兜底。
> 万一真的回落了，游戏会在画面顶部挂一条红色横幅写明原因，并自动重试连接（服务器晚一步起来也能自己恢复）。
> 启动器的独立窗口用的是单独浏览器 profile（`~/Library/Application Support/SSDZClassic/browser-profile`），
> 想彻底清掉那份兜底缓存：`bash 启动游戏.command --reset-profile`（只改名保留，不删数据）。
>
> **存档被写坏/写空时**：启动器每次启动都会做一次「存档体检」，`save/progress.json` 读不出来时，
> 自动从 `save/backup/` 里挑等级最高的快照恢复（并同步 `.min-level` 水位线）。
> 另外 `scripts/serve.js` 有水位线防线：曾达到 32 级后，任何低于水位线的存档都写不进去（除非 `?force=1`）。
>
> **导入本地存档**（系统 → 导入存档 / 从存档列表导入）：文件存档模式下会先把旧档备份到
> `save/backup/progress-<时间>.json`（`POST /__save/backup`），再用 `?force=1` 写回
> `save/progress.json` 并立即重载界面——导入完等级立刻就是新档的等级，不会「报成功但其实没换档」。
> 列表导入会把 `save/` 与 `save/backup/` 下的每一份存档都列出来（带等级和时间），挑一份就能换。

纯静态、无构建步骤。唯一需要注意的是：「存档写入文件」与「双机同步」需要本地服务
（`scripts/serve.js` 提供 `/__save`，`scripts/sync/sync.js` 提供跨设备同步）；直接静态托管也能玩，
但存档只留在浏览器里。

## 核心功能

- **战斗**：经典 1170×690 画布战斗；普攻/技能/道具，暴击、闪避、吸血、反伤、护盾、中毒、复活甲、
  绝对防御等机制。实战与离线模拟共用同一套规则（`js/sim.js`）。
- **关卡**：18 关推进，每关三名对手 + 关底；通关解锁下一关，等级不足会提示。
- **成长**：升级给属性点与礼包、武器/技能三选一、经验丸与属性丸等道具。
- **背包与装备**：部位/品质（普通→稀有→史诗→传奇）、强化、镶嵌碎片、天赋与武技。
- **装备融合**：同部位同品质三件合成更高品质一件（列表按「同部位+同品质」成组排序，方便凑三件）。
- **竞技场与天梯**：经验场、碎片场（4 人两轮）、天梯赛（积分/金杯/周榜）；体力不足会自动喝药或用票据。
- **师徒与好友**：拜师收徒领贡品、好友切磋与随机挑战。
- **挑战塔**：每层一张挑战书、连战只继承血量、对手每层随机、层间三选一增益。
- **无尽挑战塔**：免门票从 1 层冲分；限次/永久/即时三类增益，永久槽位（扩容类可 +1/+2）、
  段位机制（反伤/回复/吸血/护甲/吞噬轮转）、每 5 层商店与结算离场（抽奖卷）、每 10 层里程碑奖励、
  属性药丸槽（力/敏/速）、隐藏型「三选一强化」（强化某把武器或某个技能）。
- **双机同步**：Mac ↔ Windows 通过 ZeroTier 互推存档与游戏文件。
- **调试面板**：`Ctrl+Shift+D`（一键满级、给道具/装备、增减无尽塔增益等，不影响正式存档）。
  面板里的「增益总览」会把无尽塔本局**获得过的全部增益**摊开：当前实际提升的合计数值、
  已获得过的全部（含一次生效类、用尽消失、易碎损毁、主动失去），以及逐条的获取/消失流水。

### 无尽塔·试炼商店

- 货架 5 件 + 左下角**重新挑战币** + 刷新货架。
- **重新挑战币（50 币 / 枚）**：失败时消耗 1 枚，**回滚到该场战斗开始前**再打一次
  （血量 / 试炼币 / 分数 / 增益剩余次数 / 环境剩余场数全部还原，等于这一场没发生过）。
  每场战斗开打前会自动存一份战前快照（`run.retrySnap`），所以中途退出游戏也能续上。
  有币时失败**不会**先结算 —— 选择「放弃本局」才真正结算抽奖卷。
- **价格随机**：每件商品在基准价上做 **−3 ~ +3** 的整数偏移（7 档等概率，期望偏移 0
  → 均价不变）。价格在开店时摇一次并固定到槽位上，界面显示价 = 实际扣费。
  实现见 `TowerData.rollShopPrice()`。
- **刷新货架**：价格**逐次递增**（首次免费，之后 **10 → 20 → 30 → 40 → 50 …**，每次 +10）。
- **刷新只抬高稀有度期望，不设保底货品**：做法是「稀有度倾斜」——
  把基础权重按 `w_i × p^i` 重新归一化（`TowerData.tiltWeights`），
  `p = 1.20^(付费/10)`。`p = 1` 就是自然掉率；付得越多，整架货一起变好，
  不会出现「1 件传奇 + 4 件普通」这种结构突变（全普通货架仍然可能出现）。
  校准目标：期望史诗件数随花费**线性**上涨 —— **20 币 1 件、40 币 2 件、以此类推**。
  实测（每档 8000 次刷新，5 格）：

  | 刷新价 | 0 | 20 | 40 | 60 | 80 |
  |---|---|---|---|---|---|
  | 线性目标 | — | 1 | 2 | 3 | 4 |
  | 实测期望史诗 | 0.66 | **1.18** | **1.91** | 2.76 | 3.49 |
  | 出现传奇的概率 | 14% | 32% | 54% | 79% | 92% |

  前两档正好对上，60/80 币略低（差 0.24 / 0.51）——倾斜对高稀有度的供给有上限
  （单格期望稀有度上限是 3，越往上越难再涨）。想更贴线性可把 `rerollTiltGrowth`
  调到 `1.25`（20/40/60/80 → 1.33/2.34/3.41/4.19），代价是 20 币那一档偏高。

  质量用**加权质量分**衡量（`TowerData.shopQualityScore`，传奇权重加倍 `[0,1,2,4]`）——
  传奇自然掉率只有 3%，不能和同点数的史诗等价看待。实测质量分
  `0.52 → 0.86 → 1.29 → 1.84 → 2.31`（0/20/40/60/80 币），严格递增。
- **重新挑战币**也可以直接拿到：普通增益「重整旗鼓」立即 +1 枚、史诗增益「背水一战」立即 +5 枚
  （一次生效类，不占永久增益位，可叠加）。

### 增益池：显式归属 + 跨塔互斥

**挑战塔与无尽塔是两个独立池子。** 池子归属由 `js/tower-data.js` 的 `poolRoster(b)` 统一算出，
各池子只按这份名单取，**不再各自写谓词**（以前每个池子各写一个条件，条件之间不互斥，
导致 12 条挑战塔专属增益漏进了无尽塔商店）。

| 池子 | 含义 |
|---|---|
| `T.choice` | 挑战塔场间选择（`towerPool`） |
| `T.shop` | 挑战塔商店（塔目前没有商店，标签保留） |
| `E.choice` | 无尽塔场间选择（`endlessPool`） |
| `E.shop` | 无尽塔试炼商店（`shopPool`） |

归属规则：

- `towerOnly` → **只** `T.choice`（挑战塔专属，永不进任何无尽池）
- `endlessOnly`（或带无尽专属 mod）→ 只在 `E.*`（环境词缀 / 试炼币 / 商店 /
  重新挑战币 / 结算相关）
- `kind: 'instant'` → 不进任何池子；`battleOnly` / `shopBanned` → 不进商店
- 其余通用增益 → `T.choice + E.choice + E.shop`

**护栏（加载期直接抛错，漏标不会静默放行）**：

1. 无尽专属条目不得出现在 `T.*`；挑战塔专属不得出现在 `E.*`
2. 挑战塔池里不得含任何无尽专属 mod
3. 带无尽专属 mod 的条目必须**显式**标 `endlessOnly`（数据自解释）

实测（真跑 60 局挑战塔 + 40 局无尽塔）：挑战塔抽到 61 种（12 条专属全部覆盖）、
无尽塔抽到 69 种，**零交叉**，也没有任何池外条目。

### 挑战塔专属增益（`towerOnly` + `towerBattle`）

挑战塔是一层四场连战、打完结算，所以它的增益天然只服务**下一场战斗**：
不搞「接下来 N 场」那种叠加计时，卡面直接写「下一场战斗」，打完一场即消耗。
这些条目标了 `towerOnly`，**不会进无尽池**。

| ID | 名称 | 稀有度 | 效果 |
|---|---|---|---|
| T01 | 开局狂热 | 史诗 | 前 5 回合攻击 +50%，之后攻击 −20% |
| T02 | 烟幕 | 稀有 | 自身闪避率 +50%（乘算，上限仍 55%） |
| T03 | 疾风之靴 | 稀有 | 速度 +30% |
| T04 | 锁定打击 | 稀有 | 所有攻击必中 |
| T05 | 见血封喉 | 史诗 | 暴击率 +30%、暴击伤害 +50% |
| T06 | 金钟罩 | 稀有 | 受到伤害 −30% |
| T07 | 以血换血 | 史诗 | 反弹 35% 受到伤害 |
| T08 | 破竹之势 | 史诗 | 开局对敌人造成其 25% 最大生命的伤害 |
| T09 | 吸血獠牙 | 史诗 | 所有攻击附带 40% 吸血 |
| T10 | 背水一战 | 传奇 | 攻击 +35%、速度 +20%、受到伤害 −20% |
| T11 | 不动如山 | 传奇 | 生命上限 +35% 并回等量生命、每回合回 5% |
| T12 | 先发制人 | 普通 | 首次技能不消耗回合、第一次受伤为 0 |

**塔内一切限次增益都压到 1 次**（`uses = 1`），文案统一成「下一场战斗」，
打完一场就消失；无尽塔仍按各自的 `uses` 走。因此烙印（本局永久保留）
与 N09/N10（作用于环境词缀）也都移出了挑战塔。

### 增益池：挑战塔只收「挑战塔用得上」的

挑战塔与无尽塔机制差别很大 —— 没有环境词缀、没有试炼币/商店、没有重新挑战币、
没有本局永久槽位、也没有「按层成长」。所以 `POOLS.tower` 除了结构条件（限次类），
还要求 **不带 `endlessOnly`**：

- 受影响的条目：**晴空护符 (N09)** / **避风斗篷 (N10)**（作用于环境词缀，挑战塔没有环境）
  与 6 条**烙印**（本局永久保留）—— 现在都是 `endlessOnly`。
- 挑战塔池 = 19 条通用限次增益 + **12 条挑战塔专属** = **31 条**；无尽池 76 条（不含专属）。
- 还加了**开发期护栏** `ENDLESS_ONLY_MODS` + 断言：一旦有无尽专属 mods
  （envIgnore / coinBoostPct / instantRetry / permSlot / sellValue …）漏标 `endlessOnly`
  而混进 `towerPool`，加载时直接抛错，而不是让玩家在挑战塔里抽到一张废卡。

### 随机挑战经验：等级差已压实

`State.challengeExp(foeLevel, myLevel)` 的等级差倍率：

```
mult = clamp(1 + diff×14%, 0.3, 2.2) ^ 0.88     // EXP_DIFF_TIGHTEN = 0.88
```

指数压实让各等级差的经验更贴近同级基准（**diff = 0 时恒为 1.00，同级经验完全不变**）：

| 等级差 | −1 | 0 | +1 | +2 | +3 |
|---|---|---|---|---|---|
| 压实前 | 28 | **33** | 38 | 42 | 47 |
| 压实后 | 29 | **33** | 37 | 41 | **45** |
| 倍率 | ×0.879 | ×1.000 | ×1.121 | ×1.242 | ×1.364 |

> 压实不能更狠：竞技场验收线要求「最大等级差的体力效率严格低于竞技场 5.0/体力、
> 且不低于其 88%（4.4）」。0.85 时正好 4.40 踩线，所以取 0.88（→4.50）。

### 竞技场报名费用

报名一次付一次费，**入口只有一个**：`payArenaEntry(s, kind)`（判定与扣费在同一处，
避免出现「判定通过但没扣」的缝隙）。

| 情形 | 经验竞技场 | 碎片竞技场 |
|---|---|---|
| 体力 ≥ 30 | 扣 30 体力 | 扣 30 体力 |
| 体力 < 30、有体力药剂 | 自动喝药补到 30，**再扣 30 体力** | 同左 |
| 补不够 | 扣 **1 张英雄帖(36)** | 扣 **1 枚勇气徽章(39)** |
| 两者都没有 | 拒绝 | 拒绝 |

- 碎片竞技场**不接受英雄帖**；经验竞技场也不接受勇气徽章（被拒时两样都不扣）。
- 第二战（决赛/季军赛）不再收费。
- 扣费校验是**按实际扣掉的那一项**做的：走体力路径就核对体力正好少了 30，
  走道具路径就核对道具正好少了 1。**不要**用「体力 + 道具总和」这类跨字段粗判 ——
  自动喝药（大体力药剂 +50 再扣 30）会让总和反而变大，从而把正常报名误报成
  「报名异常，请反馈」（踩过这个坑，已改）。

### 弹窗按钮排布

所有弹窗按钮都由 `classic-ui.js` 的 `modal()` 统一排序：**主操作在最右、取消/返回在最左**。

- 分档：`取消/返回`（返回·取消·关闭·放弃）→ 最左；`延后/结束`（稍后·暂不·结束）→ 居中偏左；
  `主操作`（开始·继续·确定·挑战·闯关·再战）→ 最右。
- `cls` 里的 `muted` / `gold` 仍是加强信号；排序后**仍按原索引生成 `data-action`**，
  所以点击映射不会错位。
- 例如「常驻挑战」的 `返回 | 开始战斗`、「胜利后」的 `稍后继续 | 继续战斗`、
  通关的 `返回菜单 | 继续闯关`、竞技场战果的 `查看录像 | 返回竞技场`。

### 徒弟日供

系数按「所有徒弟等级之和 Σ」**线性插值**，经验与金松果分开（`js/state.js`）：

| Σ（等级之和） | 0 | 105 | 210（3 个满级） | 超出 |
|---|---|---|---|---|
| **经验** | 5% | 10% | **15%** | 封顶 15% |
| **金松果** | 5% | 15% | **25%** | 封顶 25% |

系数乘的是「我自己**昨天**赚到的」总经验与金松果，次日领取；多个徒弟按各自等级占 Σ 的
份额分配（累计取整，保证各份额之和正好等于总量）。

### 无尽塔积分模式

`js/tower-data.js` 的 `SCORE` 是唯一配置源，所有加分都走 `tower.js` 的 `addScore()`
（顺带记一条本局流水，界面用做提示与结算展示）。

| 来源 | 分值 | 说明 |
|---|---|---|
| 战斗胜利 | **+25** | 每赢一场 |
| 击败精英 | **+50** | x10 层第 5 场的狂战松鼠 |
| 通过一层 | **+100** | 每层 4 场全清 |
| **获取增益** | **+5 / +10 / +20 / +40** | 按稀有度（普通/稀有/史诗/传奇）；**场间选择与商店购买都算** |
| **隐藏成就·死而复生** | **+30 / +45 / +60 / +90** | 累计复活（免死/复活都算）到 3/6/9/12 次各触发一档，**12 次封顶** |
| **隐藏成就·超凡入圣** | **+100 / +150 / +220 / +300** | 某项 **buff 加成**（不含装备/等级）首次跨过 +100% / +150% / +200% / +300% |

- 层级示例：普通层 `4×25 + 100 = 200`；x10 层 `5×25 + 50 + 100 = 275`。
- 分数只增不减，结算/放弃/失败都不改动它；结算时同步到 `best`（历史最高）与
  `weekBest`（本周最高，周一重置）。
- **隐藏成就**「未达成不显示」：达成时屏幕上飘一条提示（`achievementToast`），
  结算与失败弹窗里再汇总列出本局拿到哪些、合计多少分（`achieveSummaryHtml`）。
- 成就与流水都存在 `run` 上（随存档保留），所以中途退出也不会丢。

> **防刷分**：`金蝉脱壳 (N04)` 已改成 `unique`（一局只能获得一次）——
> 原来它能被反复买到、叠到几百次免死，配合「故意挨打不死」单局能刷出 260 次复活。
> 现在一局最多 10 次（+ 每层不死鸟 1 次），复活成就的 12 次封顶才有意义。

### 无尽塔·战斗机制速查

- **环境词缀最多同时两层**（`TowerData.ENV_MAX = 2`，硬上限）：
  第 5 层起按概率触发，第 15 层起每场补满 2 条；超过 2 条会被裁剪（保留剩余场数多的）。
- **塔页面的「返回」回主界面**（挑战塔/无尽塔两处），不再回关卡页；
  胜利弹窗的「返回」本来就走主界面。
- **挑战塔碎片只掉蓝色**（id 26）：不再出白/绿（原先 72% 白、28% 蓝）。
  掉率与数量沿用 ★6 那一档，所以每层期望从「白 ~1.5 + 蓝 ~0.6」变成「蓝 ~2.1」。
- **熔核·炽壳**（`trialCore`）：第 **7** 次行动起成型，受到伤害 **−70%**，力/敏/速 +50%。
- **投掷宗师·银镖**：只带投掷类武器（流星锤 + 忍者镖），设定与实战一致。
- **易碎属性烙印**（C39~C44）：**未破碎时只有该烙印效果的 50%，破碎后吃满 100%**
  （例如力量烙印：未破碎 +4%，破碎后 +12% 并本局永久）。
  每条烙印有**各自独立的碎裂随机数**（由本局 salt + 层数 + 烙印 id 派生），
  实测固定 salt 下三条烙印分别在第 7/25/30 场碎，120 局中「同场一起碎」仅 3%（巧合概率）。
  细节与旧描述：
  - 烙印**存在**时只吃**一半**加成（如力量烙印 +4%）；
  - **损毁**后那份基础加成整份转为**本局永久保留**（实际 +12%），此后不再受烙印是否还在影响；
  - 每场 6% 损毁，且**每条烙印有自己独立的随机序列**（由本局 salt + 烙印 id 派生），
    不会再出现「一次判定把三条烙印一起打碎」。
- **轻装上阵**（C34）/ **厚积薄发**（C35）：详情里会写明当前叠层算式
  （例：`当前 4 个空槽 × 20% = 攻击 +80%（永久位 1/5）`），与实际战斗数值同源。
- 场间选择**不再有「紧急包扎」即时回血卡**，四个（无尽三个）位置全是真增益；
  需要回血就选「补给」(N08)：下一场战斗开局回复 50% 生命。
- **金蝉脱壳**（N04）限次 **3 → 10 场**。
- **全场五折**（E04）按**份数**累计：进店消耗 1 份，可叠多份折多家店；
  该店的货架价与刷新价都打五折。

### 环境词缀（无尽塔唯一的常驻负面机制）

无尽塔的负面机制只有**环境词缀**这一个来源：

- 原来的「段位机制」（荆棘反伤 / 自愈回复 / 吸血 / 护盾 / 吞噬成长）已经**全部并入环境池**，
  不再按段自动挂到敌人身上（`run.mechs` 恒为空，只作历史兼容）。
- 环境在地图与选牌页显示为胶囊，**鼠标悬停可看**：完整效果、本局摇出来的实际数值、
  数值区间、剩余场数。塔内所有弹窗都会自动绑定悬停（`tower-ui.js` 的 `modal()` 包装）。
- 每条环境的数值都是**区间**（例如荆棘反伤 10%~16%），抽取时在区间内随机取一次并固定下来，
  所以同一条环境每次出现强度略有不同。区间定义在 `js/tower-data.js` 的 `ENDLESS_ENV`，
  写法是 `key: [下沿, 上沿, 'pct'|'num']`。
- 同时最多 `ENV_MAX`（3）条；第 5 层起可能触发，第 15 层起每层固定补满 2 条。
  「无视 / 反弹 / 剥夺正向」三档 buff 仍然作用于环境。

保留这些就能完整游玩，其余都是开发/参考文件（删掉不影响运行）：


**不参与运行、可安全删除**：`references/`（含 `references/orig/`）、`tools/`、`src-tauri/`、`docs/`

## 存档目录 `save/`

| 文件 / 目录 | 是什么 | 能删吗 |
|---|---|---|
| `progress.json` | **唯一的正式存档**（帐号、背包、装备、关卡、塔进度） | ❌ 删了等于重开（读不出来时启动器会自动从 backup/ 恢复） |
| `backup/progress-YYYYMMDD-HHMMSS.json` | 同步/覆盖/导入前自动留的快照 | ✅ 可删（建议留最近几个） |
| `.server.pid` | 本地游戏服务器进程号（启动器据此判断「是否已在跑」） | ✅ 可删（之后要重启游戏） |
| `.sync.pid` | 双机同步服务进程号 | ✅ 可删 |
| `server.out.log` / `server.err.log` | 游戏服务器日志 | ✅ 可删（自动重建） |
| `sync.out.log` / `sync.err.log` | 同步服务日志 | ✅ 可删 |
| `.DS_Store` | macOS 目录元数据 | ✅ 可删 |
| `from-windows-<日期>/` | 早期从 Windows 拉过来的一次性快照 | ✅ 确认无用可删 |
| `松鼠大战存档-<日期>.json` | 手动导出的旧存档 | ✅ 可删（想留纪念可移出仓库） |

> **结论**：真正必要的只有 `progress.json`；`backup/` 是保险；pid、日志、`.DS_Store`、
> `from-windows-*`、导出档都属于**可再生/多余**文件，删掉不影响游戏。

## 双机同步（Mac ↔ Windows，走 ZeroTier）

`scripts/sync/sync.js` 有两种角色：`serve`（监听 `0.0.0.0:8788`，谁开谁才能被推）与 `push/pull`。
配置在同目录 `sync.config.json`：`name`（本机名）、`port`、`token`（两边必须一致）、`peers`（对端名 → IP）。

```bash
node scripts/sync/sync.js status win     # 自检：TCP、口令指纹、待推送/待拉取
node scripts/sync/sync.js push  win      # 本机 → 对端（存档 + 文件）
node scripts/sync/sync.js pull  win      # 对端 → 本机
node scripts/sync/sync.js restart        # 重启本机后台同步服务
```

排查顺序：**TCP 是否通**（`nc -vz <对端IP> 8788`）→ **口令是否一致**（带 `x-ssdz-token` 请求
`/api/status`：200 通、403 口令不一致，改完必须在对端**重启服务**）→ **链路质量**（ZeroTier 走中继时
RTT 可能 >1 秒且丢包，服务已对探测做重试；必要时改直连或自建 Moon 节点）。
